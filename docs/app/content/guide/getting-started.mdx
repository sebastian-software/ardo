# Getting Started

Hand this sentence to your coding agent, in a fresh repository or one you already have. The link points it to Ardo's versioned [Agent Instructions](/en/guide/agent-instructions). It adapts the [tested Basic example](/en/guide/agent-instructions#the-basic-example) and reports how typecheck, tests, and build went. You review the result like any other pull request.

<SetupPrompt>Set up Ardo in this repository following https://ardo-docs.dev/llms.txt.</SetupPrompt>

Without an agent, follow the [manual installation](#manual-installation) below.

## Prerequisites

You'll need:

- [Node.js](https://nodejs.org/) version 22.22.0 or higher
- Linux or Windows on x64/arm64, or macOS on Apple Silicon, with optional native package dependencies enabled
- [pnpm](https://pnpm.io/) (recommended) or npm/yarn

## Project Structure

Here's what an Ardo project looks like. Files under `app/routes/` become pages, `app/root.tsx` holds the site chrome, and everything else is configuration:

```text
my-docs/
├── app/
│   ├── routes/                  # Pages: .md, .mdx, and .tsx files
│   │   ├── guide/
│   │   │   └── getting-started.mdx
│   │   └── home.tsx             # Home page
│   └── root.tsx                 # Optional: theme, logo, header, sidebar, footer
├── ardo.config.ts               # Optional site configuration
├── vite.config.ts               # Optional; ardo.config.ts can hold Vite settings too
├── pnpm-workspace.yaml          # pnpm build-script allowlist, when using pnpm
├── tsconfig.json
└── package.json
```

## Manual Installation

These steps create a new docs project. In an existing repository, put it in its own package or directory: Ardo builds the docs as their own static site and shares no router or entry files with your application.

### 1. Create a new project

```bash
mkdir my-docs
cd my-docs
pnpm init
```

### 2. Install dependencies

```bash
pnpm add ardo@6
pnpm add -D typescript@6
```

Any TypeScript 6 or newer typechecks an Ardo site. The optional [API documentation](/en/guide/api-documentation#installation) needs a pinned TypeScript 7.1 nightly; switch to it when you add `api`.

### 3. Add package scripts

Ardo manages React, React DOM, and Vite as its own dependencies. Its CLI starts the development server, builds the static site, and previews the generated client output:

```json
{
  "scripts": {
    "dev": "ardo dev",
    "build": "ardo build",
    "preview": "ardo preview"
  }
}
```

When you use pnpm, add a build-script allowlist so esbuild can
prepare Vite's native dependency:

```yaml
# pnpm-workspace.yaml
packages:
  - "."

allowBuilds:
  esbuild: true
```

### 4. Add optional Ardo configuration

Ardo works without a configuration file. Add `ardo.config.ts` for site metadata, deployment, or content options. UI configuration, including the theme, navigation, sidebar, and footer, stays in JSX props in `root.tsx`:

**`ardo.config.ts`**:

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "My Documentation",
  description: "My awesome documentation site",
})
```

The site serves from the domain root. For a subpath, such as a GitHub Pages project site, set `base`; the [Deployment](/en/guide/deployment) guide covers every host.

For extra Vite plugins or Vite-specific settings, use the [`vite`](/en/guide/configuration#vite) option in `ardo.config.ts` or add a `vite.config.ts`. The Ardo CLI
adds its build integration automatically, so a custom Vite config does not need to call `ardo()`.

### 5. Create app files

Content alone is a working site: without `app/root.tsx`, Ardo renders `<ArdoRoot />`: a header with search and the theme toggle, a sidebar with one section per folder in `app/routes/`, and a footer. Ardo also renders the HTML shell around it, generates the route table, and supplies the client and server entries, the site config, and its stylesheet. Add `app/root.tsx` once you want your own theme, logo, or chrome; its default export is the root component.

**`app/root.tsx`**:

```tsx
import { ArdoRoot } from "ardo/ui"

export default function Root() {
  return <ArdoRoot />
}
```

Pass `ArdoHeader`, `ArdoSidebar`, or `ArdoFooter` as children to change any part of the chrome, for example to add a navigation link:

```tsx
import { ArdoHeader, ArdoNav, ArdoNavLink, ArdoRoot } from "ardo/ui"

export default function Root() {
  return (
    <ArdoRoot>
      <ArdoHeader>
        <ArdoNav>
          <ArdoNavLink to="/guide/getting-started">Guide</ArdoNavLink>
        </ArdoNav>
      </ArdoHeader>
    </ArdoRoot>
  )
}
```

[Layout & Navigation](/en/guide/layout-and-navigation) covers sidebar sections, the footer, and the optional `Layout` and `ErrorBoundary` exports of `root.tsx`.

**`tsconfig.json`**:

```json
{
  "extends": "ardo/tsconfig",
  "include": ["app/**/*", "*.ts"]
}
```

The preset sets `jsx`, `jsxImportSource: "ardo"`, and Ardo's type declarations, so React, MDX, and `virtual:` imports typecheck without further setup.

Import components from `ardo/ui`, runtime APIs such as `ArdoLink` and `useArdoPath` from `ardo/runtime`, and React hooks from `ardo/react`. Ardo brings its own React, so the docs package needs no React dependency of its own.

### 6. Create your first pages

Create a home page so the root URL and header logo have a destination:

**`app/routes/home.tsx`**:

```tsx
import { ArdoHero } from "ardo/ui"

export default function HomePage() {
  return (
    <ArdoHero
      name="My Documentation"
      tagline="Guides and examples for your project."
      actions={[{ text: "Get started", link: "/guide/getting-started", theme: "brand" }]}
    />
  )
}
```

Add the guide linked from your home page, header, and sidebar:

**`app/routes/guide/getting-started.mdx`**:

```markdown
---
title: Getting Started
---

# Getting Started

Welcome to your documentation site!
```

Run `pnpm dev` and open `http://localhost:5173`. You should see your home page; choose **Get started** to open the guide.

## Development

Start the development server:

```bash
pnpm dev
```

Your site will be running at `http://localhost:5173`. Changes to MDX and TSX routes flow through Vite's development server.

## Production Build

When you're ready to publish:

```bash
pnpm build
```

The output lands in `build/client/`: one prerendered `index.html` per page, a `404.html`, and the hashed assets, ready for any static host. The build should report two prerendered pages and no broken internal links. It checks every internal link and anchor in the generated HTML. Preview it locally before deploying:

```bash
pnpm preview
```

## Check and Lint

`ardo check` validates the Node.js version, the project config, and every page's frontmatter without building. Its exit code is 1 when a finding is an error. `ardo lint` reports authoring rules for Markdown and MDX pages: `missing-description`, `multiple-h1`, `heading-skip`, `code-language`, and `shell-prompt`. Its findings are warnings, and only rules that [`validation.lint`](/en/guide/configuration#validation) raises to `error` make it exit with 1. Pages opt out with [`lint`](/en/guide/frontmatter#lint). Both commands print text by default, accept `--format json` for an array of `{ file, line, column, rule, severity, message }`, and accept `--config <file>`.

```bash
pnpm exec ardo check
pnpm exec ardo lint
```

Both commands load the project config and run its plugins, as `ardo build` does, so generated pages such as the API reference may be refreshed.

## Update Checks and Usage Reporting

Before `ardo dev`, `ardo build`, and `ardo preview` start, Ardo asks a public release endpoint whether a newer stable Ardo release exists and prints a notice on stderr. It runs this check only when stderr is a terminal, outside CI, and not with `--logLevel silent`. The request carries no reporting ID, installed version, or project data. Ardo never installs updates; update the `ardo` dependency with your package manager.

`ardo update-check` runs the same check on demand. It prints the offered release as JSON with `latestVersion`, `releaseUrl`, and `stale`, or `null` when no notice is offered, including when checks are off. `null` does not prove the installed version is current. The command exits with 1 when the check fails.

`ardo telemetry` manages optional usage reporting, which is off until you consent. Reporting sends daily counts of `build`, `dev`, and `preview` commands, the Ardo version, a random reporting ID, and coarse OS, architecture, and CPU categories. It never includes command arguments, file paths, or source content. Reporting is off in CI. Ardo keeps the choice in `~/.ardo`.

| Command                       | What it does                                                           |
| ----------------------------- | ---------------------------------------------------------------------- |
| `ardo telemetry`              | Prints the disclosure and the subcommands                              |
| `ardo telemetry status`       | Shows the saved choice and effective restrictions as JSON              |
| `ardo telemetry preview`      | Shows unsent reports as JSON                                           |
| `ardo telemetry enable --yes` | Consents to reporting                                                  |
| `ardo telemetry disable`      | Withdraws consent and discards unsent counts                           |
| `ardo telemetry delete`       | Disables reporting and requests deletion of data that was already sent |

## Environment Variables

| Variable            | Effect                                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `ARDO_UPDATE_CHECK` | `0` turns off update checks, both the automatic notice and `ardo update-check`.                                                            |
| `ARDO_OFFLINE`      | Any value other than an empty string, `0`, or `false` blocks update checks and the delivery of usage reports, including deletion requests. |
| `ARDO_CACHE`        | `false`, `0`, or `off` builds without the [build cache](/en/guide/deployment#build-cache).                                                 |
| `CI`                | Any value other than an empty string, `0`, or `false` turns off the automatic update notice. `CONTINUOUS_INTEGRATION` works the same way.  |

## Next Steps

Your site is running. Now make it yours:

- Add pages, sidebar sections, a logo, and header links with [Layout & Navigation](/en/guide/layout-and-navigation#common-tasks)
- Write richer content with [Markdown & MDX](/en/guide/markdown) and the ready-made [Components](/en/guide/components)
- Change colors and styles with [Theming](/en/guide/theming), including optional [Tailwind CSS](/en/guide/theming#tailwind-css)
- [Deploy your site](/en/guide/deployment) to GitHub Pages, Netlify, Vercel, or any static host
- Generate reference pages with [API Documentation](/en/guide/api-documentation)
- Add a documentation version, a language, or an API reference with [`ardo add`](/en/guide/agent-instructions#add-a-feature-with-a-recipe)
