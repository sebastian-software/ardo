# Components

Ardo ships the components documentation pages need most: callouts, badges, cards, tabs, accordions, steps, code blocks, icons, and landing-page blocks. Each one follows the theme in light and dark mode and works with the keyboard. The examples below run in the real layout of this site, so switch the theme in the header or resize the window to see them in context.

In MDX, use the components without imports, for example `Tip`, `Card`, and `Tabs`. In TSX, import their `Ardo`-prefixed equivalents from `ardo/ui`, such as `ArdoTip`, `ArdoCard`, and `ArdoTabs`. Landing-page components are imported explicitly in both.

## Callouts

Choose the variant that matches the information. All five use the site's theme tokens and support a custom title.

<Tip title="Keep related instructions together">
  Use a callout for a short piece of guidance that belongs next to the task.
</Tip>
<Info title="Static output">Ardo prerenders routes during the production build.</Info>
<Note title="Optional configuration">
  A route can use frontmatter to override its title and sidebar position.
</Note>
<Warning title="Check the destination">
  Review the deployment base path before publishing a versioned site.
</Warning>
<Danger title="Destructive example">
  Export your data before replacing a directory that contains work you need.
</Danger>

```mdx
<Tip title="Keep related instructions together">Put the guidance next to the task.</Tip>
```

The same variants are available as [GitHub-style alerts](/en/guide/markdown#callouts) in plain Markdown.

## Badges

Badges add a compact status to a sentence. They stay inline: <Badge>New</Badge> <Badge variant="success">Stable</Badge> <Badge variant="warning">Preview</Badge> <Badge variant="danger">Deprecated</Badge> <Badge variant="info">Reference</Badge> <Badge icon="✦">With icon</Badge>.

```mdx
<Badge variant="success">Stable</Badge>
<Badge icon="✦">With icon</Badge>
```

## Cards

Use linked cards for navigation and static cards for a short summary. The grid collapses to one column on small screens.

<CardGroup cols={2}>

  </Card>
  <Card title="Configuration" icon="Settings" href="/en/guide/configuration">
    Configure routes, API reference, metadata, and deployment output.
  </Card>
  <Card title="Local components" icon="Code">
    Import components from the docs project or an installed component package.
  </Card>
  <Card
    title="Source repository"
    icon={<Github size={20} />}
    href="https://github.com/sebastian-software/ardo"
  >
    Review the implementation and contribute changes on GitHub.
  </Card>
</CardGroup>

```mdx
<CardGroup cols={2}>
  <Card title="Getting Started" icon="Rocket" href="/guide/getting-started">
    Set up a documentation site.
  </Card>
  <Card title="Local components" icon="Code">
    Import components into your MDX routes.
  </Card>
</CardGroup>
```

| Component   | Prop        | Type                  | Purpose                                                              |
| ----------- | ----------- | --------------------- | -------------------------------------------------------------------- |
| `CardGroup` | `cols`      | `1 \| 2 \| 3 \| 4`    | Preferred number of columns on wide screens. Defaults to `2`.        |
| `CardGroup` | `children`  | `ReactNode`           | Cards to render in the responsive grid.                              |
| `Card`      | `title`     | `string`              | Required card heading.                                               |
| `Card`      | `href`      | `string`              | Optional internal or external destination. Makes the card clickable. |
| `Card`      | `icon`      | `string \| ReactNode` | Registered icon name or custom React node.                           |
| `Card`      | `children`  | `ReactNode`           | Body content.                                                        |
| `Card`      | `className` | `string`              | Additional CSS class.                                                |

        <CodeBlock language="bash" code="npm install ardo" />

    </TabPanels>
  </Tabs>

```mdx
<Tabs defaultValue="pnpm">
  <TabList>
    <Tab value="pnpm">pnpm</Tab>
    <Tab value="npm">npm</Tab>
  </TabList>
  <TabPanels>
    <TabPanel value="pnpm">pnpm add ardo</TabPanel>
    <TabPanel value="npm">npm install ardo</TabPanel>
  </TabPanels>
</Tabs>
```

For custom components that create tabs or panels internally, set `defaultValue` on `Tabs`
and give each tab/panel pair matching explicit `value` props.

| Component  | Prop           | Type        | Purpose                                                                |
| ---------- | -------------- | ----------- | ---------------------------------------------------------------------- |
| `Tabs`     | `defaultValue` | `string`    | Initial active tab value. Defaults to the first tab.                   |
| `Tabs`     | `children`     | `ReactNode` | A `TabList` and matching `TabPanels`.                                  |
| `Tab`      | `value`        | `string`    | Stable value that matches a `TabPanel`. Optional when order is stable. |
| `Tab`      | `children`     | `ReactNode` | Tab label.                                                             |
| `TabPanel` | `value`        | `string`    | Matching value for the tab content. Optional when order matches tabs.  |
| `TabPanel` | `children`     | `ReactNode` | Panel content.                                                         |

## Code Blocks

Code blocks include a copy button that copies the code without the title or line numbers. Markdown fences are highlighted at build time; the `CodeBlock` component also accepts a string directly.

<GalleryPreview id="gallery-code" label="Code example">
  <CodeBlock language="bash" title="terminal" code="pnpm add ardo" />
</GalleryPreview>

```mdx
<CodeBlock language="bash" title="terminal" code="pnpm add ardo" />
```

Use `CodeGroup` for related snippets with their own file names:

<GalleryPreview id="gallery-code-group" label="Code group example">
  <CodeGroup labels="Configuration,Home route">
    <CodeBlock
      language="typescript"
      title="ardo.config.ts"
      code={
        'import { defineArdoConfig } from "ardo/config"\n\nexport default defineArdoConfig({ title: "My docs" })'
      }
    />
    <CodeBlock
      language="markdown"
      title="app/routes/home.md"
      code={"# Welcome\n\nStart with your first guide."}
    />
  </CodeGroup>
</GalleryPreview>

Markdown fences support titles, highlighted lines, line numbers, and wrapped agent prompts; see [Syntax Highlighting](/en/guide/markdown#syntax-highlighting).

### In TSX Routes

The `ArdoCodeBlock` component can be used directly in `.tsx` route files. Just write the code as children — no template literals or special escaping needed:

```tsx
import { ArdoCodeBlock } from "ardo/ui"

export default function MyPage() {
  return (
    <ArdoCodeBlock language="tsx">
      export function Hello() {
        return <div>Hello world!</div>
      }
    </ArdoCodeBlock>
  )
}
```

The `ardo:codeblock-highlight` Vite plugin processes ArdoCodeBlock **before the JSX parser runs**, so the children can contain any syntax (`<`, `{`, `>`, etc.) without causing errors. Common indentation is stripped automatically.

The `code` prop and template literal children are also supported:

```tsx
<ArdoCodeBlock code="const x = 42" language="typescript" />
```

If the `language` prop is dynamic (from a variable), build-time highlighting is skipped and the code renders as plain text.

## Icons

Ardo includes 50 [Streamline Core Line](https://streamlinehq.com/icons/core-line) icons for documentation content. They share the same 14 × 14 grid, rounded strokes, and `currentColor` as the built-in sidebar and header controls.

These are the registered content icons, shown at 14 and 28 pixels. Use the visible name with `Icon`, or import its component from `ardo/icons`.

<GalleryIcons />

### Use in MDX

All 50 Core icons are available automatically. Use their names directly without imports or a registration call:

```mdx
<Icon name="Zap" size={20} />
<Card title="Deploy your site" icon="Rocket">
  Build the static output and publish it to your host.
</Card>
```

| Component | Prop      | Type                           | Purpose                                 |
| --------- | --------- | ------------------------------ | --------------------------------------- |
| `Icon`    | `name`    | `string`                       | Registered icon name.                   |
| `Icon`    | `size`    | `number`                       | Optional rendered icon size.            |
| `Icon`    | SVG props | `SVGAttributes<SVGSVGElement>` | Passed to the registered SVG component. |

### Use in React

```tsx
import { BookOpen, Rocket, ShieldCheck } from "ardo/icons"

<BookOpen size={20} />
<Rocket size={28} className="launch-icon" />
<ShieldCheck size={20} aria-label="Security checks passed" />
```

The default size is 24 px. Set `size` to a number or CSS length, or pass native `width` and `height` attributes. Icons inherit the surrounding text color. They are decorative by default; supply `aria-label` or `aria-labelledby` when the icon conveys information without accompanying text.

`ArdoIcon` renders a registered icon by name, for example inside a link:

```tsx
import { ArdoIcon, ArdoLink } from "ardo/ui"

export function LaunchLink() {
  return (
    <ArdoLink to="/guide/getting-started">
      <ArdoIcon name="Rocket" aria-hidden /> Get started
    </ArdoLink>
  )
}
```

### Add or Override Icons

Use `registerIcons()` in `app/root.tsx` to add other React SVG components or brand icons:

```tsx
import { Github } from "ardo/icons"
import { registerIcons } from "ardo/ui"

registerIcons({ Github })
```

Then use `<Icon name="Github" />` in MDX. Registering an existing name overrides its built-in component. For icons from another library, declare that library as a direct dependency and import its components in your registration module.

`getRegisteredIconNames()` returns the built-in and custom registry keys when you need to validate user-facing configuration.

## Hero and Features

`Hero` and `Features` compose landing pages. This compact hero shows its secondary text and actions; on a home page, add `name` for the main heading and optionally an image or version badge.

<GalleryPreview id="gallery-hero" label="Hero example">
  <GalleryHero
    text="Your project, clearly explained."
    tagline="Guides, API reference, and live React examples. Give readers a clear place to start."
  />
</GalleryPreview>

Pass `image={{ light, dark, alt }}` to provide a variant for each theme. The image
follows the theme selected in the header. A string URL or `{ light, alt }` uses
one image in both themes; a React element can render an inline illustration.

  >
    Generate HTML and assets for your static host.
  </FeatureCard>
</Features>

```mdx
import { ArdoHero as Hero } from "ardo/ui"

<Hero
  name="My project"
  text="Documentation for your team"

/>
```
