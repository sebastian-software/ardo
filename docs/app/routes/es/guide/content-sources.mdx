# Fuentes de contenido

Usa fuentes de contenido cuando el Markdown que quieres publicar ya pertenece a otra parte del repositorio: ADR, guías de paquetes, registros de cambios o documentación compartida. Ardo genera una vista de rutas de solo lectura durante la compilación y el archivo original sigue siendo la fuente de referencia.

## Asociar un directorio {#map-a-directory}

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "Workspace Docs",
  content: [{ from: "../../adr", to: "decisions" }],
})
```

La fuente `../../adr/0001-routing.md` se convierte en `/decisions/0001-routing`. El frontmatter existente se conserva. Si no lo hay, Ardo deduce el título de la primera cabecera o del nombre de archivo y usa un prefijo numérico del nombre para ordenar la barra lateral.

## Integración en la compilación {#what-participates}

El Markdown y MDX asociado se convierte en rutas generadas normales. Participa en la barra lateral, la búsqueda por sección, el sitemap, las exportaciones para LLM, las redirecciones, la comprobación de enlaces internos y la [validación del frontmatter](/es/guide/frontmatter).

## Límite de los archivos generados {#generated-file-boundary}

Ardo escribe los archivos asociados en el directorio `to` elegido y lo marca como generado. Edita la fuente original, nunca la ruta generada. El plugin no elimina directorios de destino escritos a mano que contengan archivos. Usa un prefijo específico, como `decisions/`.

## Alcance {#boundaries}

Las fuentes de contenido no descargan URL remotas, no sustituyen un CMS ni transforman tipos de archivo arbitrarios. Asocian archivos locales; las [colecciones con esquema](#schema-backed-collections) añaden validación y registros tipados.

## Colecciones con esquema {#schema-backed-collections}

Usa `collections` cuando los mismos archivos Markdown locales deban generar rutas y estar disponibles como datos tipados de compilación en una ruta React personalizada:

```ts
import { defineArdoConfig } from "ardo/config"
import { defineCollection } from "ardo/vite"

const recipes = defineCollection<{ title: string }>({
  from: "../../recipes",
  to: "recipes",
  schema: (data) => ({ title: String(data.title) }),
})

export default defineArdoConfig({ title: "Docs", collections: { recipes } })
```

Importa `getCollection<T>()` de `virtual:ardo/collections` en una ruta personalizada para leer registros generados y tipados:

```tsx
import { getCollection } from "virtual:ardo/collections"

const recipes = getCollection<{ title: string }>("recipes")
```

Las colecciones siguen siendo locales y estáticas: el esquema se ejecuta durante la compilación, mientras que las páginas generadas siguen los procesos habituales de barra lateral, búsqueda, sitemap, redirecciones y exportaciones para LLM. Las rutas de origen son relativas al proyecto, así que el módulo virtual no expone las rutas absolutas del autor.

Añade estas opciones al [ejemplo Basic](/es/guide/agent-instructions#the-basic-example) de la misma versión. Los archivos originales siguen siendo la referencia: la compilación genera las páginas `/recipes/*` a partir de ellos y una ruta React personalizada puede mostrar los mismos registros.
