This website is available in English, German, French, and Spanish. Choose a language in the header or mobile menu. Ardo keeps the same page, query string, and fragment when you switch languages.

## Static Language Routes

Configure locales in `ardo.config.ts` or the `ardo()` Vite plugin:

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "My Docs",
  i18n: {
    defaultLocale: "en",
    locales: [
      { id: "en", label: "English" },
      { id: "de", label: "Deutsch" },
      { id: "fr", label: "Français" },
      { id: "es", label: "Español" },
    ],
  },
})
```

Put matching routes under `app/routes/en/`, `app/routes/de/`, `app/routes/fr/`, and `app/routes/es/`. Keep route slugs identical across languages. Ardo requires a complete route tree and reports missing pages during the build. It does not silently substitute another language.

The V6 deployment uses `/v6/en/`, `/v6/de/`, `/v6/fr/`, and `/v6/es/`. Older documentation versions retain their original language and URLs.

## UI, Search, and Metadata

Use `useArdoLocale()` from `ardo/runtime` for the active locale, including during server rendering. Pass localized labels to `<ArdoRoot labels={...}>` for navigation, search, callouts, copy controls, and page actions. Ardo formats last-updated dates with the route locale.

Search loads only the active language's index when readers focus the field or enter a query. Generated HTML carries the correct `lang`, canonical URL, and alternate-language links. Code identifiers and import paths remain unchanged. The API reference is generated from English source comments and says so in each translated interface.

## One MDX Source with Palamedes

This example is compiled by Palamedes from one English MDX file. Its paragraphs and rich-text placeholders come from the language catalogs; the React component stays intact:

<Welcome />

Palamedes and Ardo each own a complete MDX compiler. This site lets Ardo compile documentation routes so syntax highlighting, heading anchors, the outline, and search use the same source. It imports this small example with `?palamedes` through a dedicated Vite adapter, letting Palamedes own that module. Imported components are explicit, as required by Palamedes' MDX compiler.

The documentation routes are authored as localized Markdown and MDX. Shared interface copy uses Palamedes macros and PO catalogs in `docs/app/i18n/`. This avoids sending all four catalogs to every reader: each document loads its own locale.

## Server Render Context

A site can export `withRenderContext` from `app/server.ts` to scope work around one complete page render. This module is only included in the server bundle. Metadata resolution and suspended React components run inside the same context:

```ts
import type { ArdoServerRenderContext } from "ardo/runtime"
import { createServerI18nScope } from "@palamedes/runtime/server"

const scope = createServerI18nScope()

export async function withRenderContext({ path, render }: ArdoServerRenderContext) {
  const i18n = await loadI18n(path.split("/")[1] ?? "en")
  return scope.run(i18n, render)
}
```

Here `loadI18n` is the site's catalog loader. Use one immutable instance per locale or a fresh instance per request. Do not activate a process-wide mutable locale: parallel renders would otherwise mix languages. In the browser, load the document's catalog and call `setClientI18n` before hydration.

## Maintain Translations

From the repository root:

```bash
pnpm --filter ardo-docs i18n:extract
pnpm --filter ardo-docs i18n:check
```

Extraction updates the source messages and preserves existing translations. The catalog audit checks completeness, ICU syntax, plural arguments, and rich-text placeholders. Update every localized route when its source changes, then build the site and run the language-switching browser tests.
