# Theming

Ardos Standardtheme ist vollständig. Du passt es dort an, wo du die Website komponierst: in `app/root.tsx` mit React-Props und importierten Dateien. Beginne mit wenigen Farben und verfeinere nach Bedarf:

1. **`theme`-Prop:** Farben, Sättigung, Callouts, Schriften und alle Designtokens.
2. **Logo und Favicon:** importierte Dateien mit Vite-Fingerprints.
3. **CSS-Variablen und Vanilla Extract:** eigene Styles mit Ardos Tokens.
4. **Tailwind CSS:** Utility-Klassen für eigene Seiten und Komponenten.

Eigene React-Komponenten für Kopfzeile, Seitenleiste und Fußzeile behandelt [Layout und Navigation](/de/guide/layout-and-navigation#replace-parts-of-the-chrome).

## Farben, Logo und Favicon {#colors-logo-and-favicon}

**`app/root.tsx`**:

```tsx
import { ArdoRoot } from "ardo/ui"

import logo from "./assets/logo.svg"

export default function Root() {
  return (
    <ArdoRoot theme={{ color: "blue", accent: "teal", neutral: "slate" }} logo={logo} icon={logo} />
  )
}
```

`theme` setzt drei Farbtöne: `color` für Links, Tasten und Fokusringe, `accent` für weitere Highlights und Codeflächen und `neutral` für Hintergründe, Rahmen, Text, Kopfzeile und Seitenleiste. Daraus leitet Ardo alle übrigen Farben für Hell und Dunkel ab.

`logo` und `icon` nehmen importierte Dateien. Vite versieht URLs mit Fingerprints, damit neue Logos nach dem Deployment statt aus altem Cache erscheinen. Hier dient das Logo auch als Favicon. Für Wortmarken nutze ein eigenes quadratisches `icon`.

- **Helles und dunkles Logo:** `logo={{ light: logoLight, dark: logoDark }}`.
- **iOS-Startbildschirme:** `appleTouchIcon` nimmt ein 180×180-PNG.
- **Ohne `icon`:** Ardo verlinkt seine Eulenicons. Direkte Zugriffe auf `/favicon.ico` liefern ebenfalls die Eule, außer du hinterlegst eine eigene Datei in `public/`.

Die Konfigurationsdatei enthält weder Farben noch Assets. Sie regelt Build-Daten wie Titel, Basispfad, Versionen und API-Referenz.

## Farbtöne und Voreinstellungen {#hues-and-presets}

`color`, `accent` und `neutral` akzeptieren Voreinstellungen oder OKLCH-Winkel von `0` bis `360`:

```tsx
<ArdoRoot theme={{ color: 240, accent: 170, neutral: 260 }} />
```

Voreinstellungen: `berry` (Standard), `red`, `orange`, `amber`, `green`, `teal`, `blue`, `indigo`, `purple`, `pink`, `slate` und `gray`. `gray` ist ohne Farbton, `slate` ein gedämpftes Blau.

Ohne `accent` wählt Ardo eine Komplementärfarbe, ohne `neutral` eine schwache Markenfärbung. `neutral: "gray"` bleibt völlig neutral.

## Sättigung {#saturation}

`chroma` steuert die Sättigung. `1` erhält die Palette, kleinere Werte beruhigen sie, `0` macht eine Rolle grau. Eine Zahl gilt für `color` und `accent`; das Objekt setzt jede Rolle einschließlich `neutral`:

```tsx
<ArdoRoot
  theme={{
    color: "green",
    accent: "orange",
    neutral: 95,
    chroma: { color: 0.4, accent: 2, neutral: 1.6 },
  }}
/>
```

Über `1` können Farben wie Türkis den sRGB-Farbraum verlassen. Prüfe deshalb den Linkkontrast, wenn du `color` erhöhst.

## Callout-Farben {#callout-colors}

Callouts behalten eigene Farben, damit Warnungen bei jeder Marke erkennbar bleiben. Bei Konflikten mit dem Akzent setzt `status` neue Farbtöne. Ardo leitet Text, Fläche und Rahmen für beide Modi ab:

```tsx
<ArdoRoot theme={{ accent: 38, status: { warning: 72 } }} />
```

`status` akzeptiert `tip`, `warning`, `danger` (Vorsicht), `info` (wichtig) und `note` als Voreinstellung oder Farbton. Alle Voreinstellungen halten mindestens 4,5:1 Textkontrast.

## Schriften {#fonts}

Lade eine Schrift als Abhängigkeit und setze ihren Namen in `fonts`, etwa mit [Fontsource](https://fontsource.org/):

```bash
pnpm add @fontsource-variable/inter
```

```tsx title="app/root.tsx"
import "@fontsource-variable/inter"
import { ArdoRoot } from "ardo/ui"

export default function Root() {
  return <ArdoRoot theme={{ fonts: { body: '"Inter Variable", system-ui, sans-serif' } }} />
}
```

Überschriften folgen `body`, sofern `heading` fehlt. `mono` bestimmt die Schrift für Codeblöcke und Inline-Code.

## Designtokens {#design-tokens}

`tokens` setzt Ardos Designtokens für beide Modi. `light` und `dark` überschreiben sie einzeln; dort gehören die meisten Farben hin:

```tsx title="app/root.tsx"
import { ArdoRoot, type ArdoThemeProps } from "ardo/ui"

const theme: ArdoThemeProps = {
  tokens: {
    radius: { sm: "0px", base: "0px", lg: "0px" },
    color: {
      shadowSm: "0 0 0 0 transparent",
      shadowMd: "0 0 0 0 transparent",
      shadowLg: "0 0 0 0 transparent",
    },
  },
  light: { color: { bg: "#fbfbf8", text: "#101010", brand: "#0038ff", brandGradient: "#0038ff" } },
  dark: { color: { bg: "#101010", text: "#fbfbf8" } },
}

export default function Root() {
  return <ArdoRoot theme={theme} />
}
```

TypeScript meldet unbekannte Tokens; Ardo lehnt sie auch beim Rendern ab. `shadowSm`, `shadowMd`, `shadowLg` und `codeShadow` sind vollständige `box-shadow`-Werte. Für keinen Schatten nutze `0 0 0 0 transparent`; `none` bricht zusammengesetzte Schatten. `brandGradient` akzeptiert auch eine einfache Farbe.

Ardos Dokumentation nutzt damit die Eulenpalette: Oliv, Terrakotta, leicht warmes Weiß und Senfgelb für Warnungen:

```tsx
const theme: ArdoThemeProps = {
  color: 123,
  accent: 38,
  neutral: 95,
  chroma: { color: 0.4, accent: 2, neutral: 1.6 },
  status: { warning: 72 },
  light: { color: { codeBg: "oklch(0.973 0.006 95)", codeBorder: "oklch(0.9 0.009 95)" } },
  dark: { color: { codeBg: "oklch(0.205 0.01 95)", codeBorder: "oklch(0.31 0.014 95)" } },
}
```

## Eigene Root-Komponente {#your-own-root}

`ArdoRoot` rendert das Theme automatisch. Eigene Hüllen aus etwa `ArdoProvider` und `ArdoLayout` rendern `<ArdoTheme>` mit denselben Props, setzen `logo` auf `ArdoHeader` und übergeben das Favicon an die HTML-Hülle `ArdoRootLayout`:

```tsx title="app/root.tsx"
import type { ReactNode } from "ardo/react"
import { ArdoRootLayout, ArdoTheme } from "ardo/ui"

import icon from "./assets/icon.svg"
import { SiteShell } from "./site-shell"

export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout icon={icon}>{children}</ArdoRootLayout>
}

export default function Root() {
  return (
    <>
      <ArdoTheme color="blue" neutral="slate" />
      <SiteShell />
    </>
  )
}
```

## CSS-Variablen {#css-variables}

Jeder Token ist auch eine CSS-Variable wie `--ardo-hue-brand` oder `--ardo-color-bg`. Eigene Styles überschreiben Ardos `ardo`-Kaskadenebene ohne zusätzliche Spezifität. Farben auf `:root` gelten deshalb auch dunkel; grenze Farben je Modus ein:

```css
:root:not(.dark) {
  --ardo-color-bg: oklch(0.99 0.004 95);
}

.dark {
  --ardo-color-bg: oklch(0.17 0.006 95);
}
```

Variablen für Farbton, Sättigung, Layout und Typografie sind auf `:root` sicher. Häufige Werte und ihre Standards:

```css
:root {
  /* Hues */
  --ardo-hue-brand: 356;
  --ardo-hue-accent: 230;
  --ardo-hue-neutral: 356;
  --ardo-hue-tip: 155;
  --ardo-hue-warning: 45;
  --ardo-hue-danger: 25;
  --ardo-hue-info: 220;
  --ardo-hue-note: 270;

  /* Chroma multipliers: 1 is the default saturation, 0 is gray */
  --ardo-chroma-brand: 1;
  --ardo-chroma-accent: 1;
  --ardo-chroma-neutral: 1;

  /* Layout */
  --ardo-layout-sidebarWidth: 20rem;
  --ardo-layout-tocWidth: 15rem;
  --ardo-layout-contentMaxWidth: 36em; /* em: the measure follows each element's font size */
  --ardo-layout-pageMaxWidth: 69rem; /* header, hero, features, footer on bare pages */
  --ardo-layout-headerHeight: 3.5rem;

  /* Typography */
  --ardo-font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", ...;
  --ardo-font-familyHeading: var(--ardo-font-family);
  --ardo-font-mono: ui-monospace, SFMono-Regular, ...;
  --ardo-font-lineHeight: 1.65;

  /* Border radius */
  --ardo-radius-sm: 0.25rem;
  --ardo-radius-base: 0.5rem;
  --ardo-radius-lg: 0.75rem;
}
```

## Vanilla-Extract-Tokens {#vanilla-extract-tokens}

Ardos Oberfläche nutzt [Vanilla Extract](https://vanilla-extract.style/). Alle Tokens lassen sich typsicher aus `ardo/theme` importieren – mit Autovervollständigung und Compilerfehlern bei falschen Verweisen.

Die CLI enthält das Vanilla-Extract-Plugin. `.css.ts` funktioniert ohne weitere Vite-Konfiguration. Installiere zuvor die Styling-API im Dokumentationspaket:

```bash
pnpm add @vanilla-extract/css
```

### Tokens in eigenen Stilen nutzen {#using-tokens-in-your-styles}

Erstelle eine `.css.ts`-Datei im Projekt:

```ts
// styles/custom.css.ts
import { style, globalStyle } from "@vanilla-extract/css"
import { vars } from "ardo/theme"

export const highlight = style({
  background: vars.color.brandSubtle,
  borderLeft: `3px solid ${vars.color.brand}`,
  padding: "16px",
  borderRadius: vars.radius.base,
})

// Override Ardo's default styles
globalStyle(".ardo-content a", {
  color: vars.color.brand,
  textDecoration: "underline",
})
```

### Stylesheet-Zuständigkeit und Kaskade {#stylesheet-ownership-and-cascade}

Ardo lädt `ardo/ui/styles.css` nach den CSS-Importen des Root-Moduls. Es enthält Oberfläche, Reset und Theme im Layer `ardo`. Komponentenimporte oder ein zusätzlicher eigener Import laden keine zweite Kopie.

Normales CSS ohne Layer hat unabhängig von der Ladereihenfolge Vorrang. Du kannst etwa `.ardo-footer` direkt überschreiben. Bei eigenen Layern lege deren Reihenfolge im ersten Root-Stylesheet fest, zum Beispiel `@layer ardo, app;`.

### Stabile CSS-Anpassungspunkte {#stable-override-hooks}

Generierte Vanilla-Extract-Klassennamen sind Implementierungsdetails. Nutze für gezielte Anpassungen die stabilen Klassen:

| Bereich                                    | Klassen                                                                                                           |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| Kopfzeile und Navigation                   | `.ardo-header`, `.ardo-nav`, `.ardo-mobile-panel`                                                                 |
| Seitenleiste                               | `.ardo-sidebar`, `.ardo-sidebar-tabs`, `.ardo-sidebar-panel`, `.ardo-sidebar-header`, `.ardo-sidebar-nav`         |
| Dokumentraster und optionale rechte Spalte | `.ardo-doc-page`, `.ardo-page-rail`, `.ardo-page-rail-section`                                                    |
| Artikel und Einleitung                     | `.ardo-content`, `.ardo-content-header`, `.ardo-content-title`, `.ardo-content-description`, `.ardo-content-body` |
| Inhaltsverzeichnis                         | `.ardo-toc`                                                                                                       |
| Codeblöcke                                 | `.ardo-code-block`, `.ardo-code-title`, `.ardo-code-wrapper`, `.ardo-copy-button`                                 |
| Fußzeile                                   | `.ardo-footer`                                                                                                    |

Diese Klassen sind Anpassungspunkte, keine eigene Styling-API. Nutze zuerst Tokens und Props und anschließend diese Selektoren für projektspezifische Änderungen.

Begrenze Anpassungen in einem bestehenden Designsystem auf den Website-Wrapper. Hat die Website bereits eine Abschnittsnavigation, darf sie `.ardo-sidebar-tabs` ausblenden, solange alle Bereiche auf Desktop und Mobilgeräten erreichbar bleiben. Theme-Variablen für Body-Portale wie die Suche gehören auf `className` von `ArdoRootLayout`.

### Token-Kategorien {#available-token-categories}

`vars` enthält Tokens für:

- **`vars.color`** — Farben, Flächen, Text, Rahmen, Schatten und semantische Farben.
- **`vars.hue`** — Marken-, Akzent-, Neutral- und Callout-Farbtöne.
- **`vars.chroma`** — Sättigungsfaktoren für Marke, Akzent und neutrale Farben.
- **`vars.layout`** — Seitenleisten-, Inhaltsverzeichnis-, Inhalts- und Seitenbreite sowie Kopfzeilenhöhe.
- **`vars.transition`** — Schnelle, normale und langsame Übergänge.
- **`vars.font`** — Text-, Überschriften- und Codeschriften, Grundgröße und Zeilenhöhe.
- **`vars.fontSize`** — Typografieskala von `xs` bis `4xl`.
- **`vars.space`** — Abstandsskala von `xs` bis `4xl`.
- **`vars.radius`** — Radien `sm`, `base`, `lg`, `xl` und `full`.

## Tailwind CSS {#tailwind-css}

[Tailwind CSS v4](https://tailwindcss.com/) ist optional für eigene Landingpages, Beispiele, Komponentendemos und MDX. Behalte beim Ardo-Einstieg deine bestehende Styling-Lösung bei.

Ardo gestaltet seine Oberfläche mit Vanilla Extract. Tailwind ist für deine Inhalte gedacht: Styling direkt in React, ohne ein zweites Themesystem.

### Einrichtung {#setup}

Installiere `tailwindcss` und `@tailwindcss/vite` als Entwicklungsabhängigkeiten und konfiguriere:

1. `@tailwindcss/vite` in `vite.config.ts` unter `plugins`.
2. `tailwindcss` als Entwicklungsabhängigkeit.
3. `app/app.css` mit Tailwinds Theme- und Utility-Layern.

```css title="app/app.css"
@layer theme, base, ardo, components, utilities;
@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/utilities.css" layer(utilities);

/* Follow Ardo's theme toggle, which sets the .dark class on <html>. */
@custom-variant dark (&:where(.dark, .dark *));
```

Importiere die Datei in `app/root.tsx`. Da Ardo sein Stylesheet danach lädt, gilt die hier deklarierte Layerreihenfolge: Nenne `ardo` vor `components` und `utilities`, damit Utility-Klassen gegen die Inhaltsstile gewinnen.

Tailwinds Variante `dark:` folgt standardmäßig dem Betriebssystem. Mit `@custom-variant` folgt sie Ardos Theme-Schalter und wechselt gemeinsam mit der Website.

### Beispiele {#examples}

#### Hinweisbox in MDX {#callout-box-in-mdx}

Das funktioniert direkt in jeder `.mdx`-Datei:

```html
<div
  className="flex gap-3 rounded-lg border border-blue-200 bg-blue-50 p-4 dark:border-blue-800 dark:bg-blue-950"
>
  <span className="text-xl">💡</span>
  <div>
    <p className="font-semibold text-blue-900 dark:text-blue-100">Good to know</p>
    <p className="text-sm text-blue-700 dark:text-blue-300">
      Tailwind classes work in MDX files, TSX components, and anywhere else in your Ardo project.
    </p>
  </div>
</div>
```

#### Eigener Hero-Bereich {#custom-hero-section}

Erstelle einen Landingpage-Kopf ohne eigene CSS-Zeilen:

```tsx title="app/routes/home.tsx"

export default function Home() {
  return (
    <div className="flex min-h-[60vh] flex-col items-center justify-center gap-6 text-center">

        <ArdoLink
          to="/guide/getting-started"
          className="rounded-lg bg-blue-600 px-5 py-2.5 text-sm font-medium text-white hover:bg-blue-700"

        >
          GitHub
        </a>
      </div>
    </div>
  )
}
```

### Warum ohne Preflight? {#why-no-preflight}

Ardo bringt Basisstile für Typografie, Überschriften, Links, Listen und Codeblöcke mit. Tailwinds Preflight-Reset würde damit kollidieren und das Standardbild verändern.

Wenn du alle Stile einer stark angepassten Website selbst kontrollierst, kannst du Preflight in `app/app.css` aktivieren:

```css title="app/app.css"
@layer theme, base, ardo, components, utilities;
@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "tailwindcss/utilities.css" layer(utilities);
```

Ardos Inhaltsstile setzen Listenzeichen, Tabellenrahmen, Code und Abstände ausdrücklich. Markdown bleibt auch unter einem Host-Reset lesbar. `ardo` liegt nach `base`, sodass Preflight diese Stile nicht aufhebt, und vor `utilities`, damit angewendete Utility-Klassen gewinnen.
