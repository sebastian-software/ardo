# Komponenten

Ardo liefert Callouts, Badges, Karten, Tabs, Akkordeons, Schritte, Codeblöcke, Icons und Landingpage-Bausteine. Sie folgen dem hellen und dunklen Theme und sind per Tastatur bedienbar. Die Beispiele laufen im echten Website-Layout. Wechsle das Theme oder ändere die Fenstergröße, um das Verhalten zu sehen.

In MDX verwendest du etwa `Tip`, `Card` und `Tabs` ohne Import. In TSX importierst du `ArdoTip`, `ArdoCard` und `ArdoTabs` aus `ardo/ui`. Landingpage-Komponenten werden in beiden Formaten explizit importiert.

## Callouts {#callouts}

Wähle die passende Variante. Alle fünf nutzen die Theme-Tokens der Website und unterstützen eigene Titel.

<Tip title="Zusammengehörige Hinweise bündeln">
  Platziere kurze Hilfestellungen direkt bei der Aufgabe.
</Tip>
<Info title="Statische Ausgabe">Ardo rendert Routen beim Produktionsbuild vor.</Info>
<Note title="Optionale Konfiguration">
  Frontmatter kann Titel und Position in der Seitenleiste überschreiben.
</Note>
<Warning title="Ziel prüfen">
  Prüfe vor der Veröffentlichung den Basispfad der versionierten Website.
</Warning>
<Danger title="Destruktives Beispiel">
  Exportiere deine Daten, bevor du einen Ordner mit benötigten Dateien ersetzt.
</Danger>

```mdx
<Tip title="Keep related instructions together">Put the guidance next to the task.</Tip>
```

Dieselben Varianten gibt es als [GitHub-Hinweise](/de/guide/markdown#callouts) in reinem Markdown.

## Badges {#badges}

Badges ergänzen einen kompakten Status im Text: <Badge>Neu</Badge> <Badge variant="success">Stabil</Badge> <Badge variant="warning">Vorschau</Badge> <Badge variant="danger">Veraltet</Badge> <Badge variant="info">Referenz</Badge> <Badge icon="✦">Mit Icon</Badge>.

```mdx
<Badge variant="success">Stable</Badge>
<Badge icon="✦">With icon</Badge>
```

## Karten {#cards}

Verlinkte Karten dienen der Navigation, statische einer kurzen Zusammenfassung. Das Raster wird auf schmalen Bildschirmen einspaltig.

<CardGroup cols={2}>
  <Card title="Erste Schritte" icon="Rocket" href="/de/guide/getting-started">
    Erstelle deine Dokumentation mit einem Assistenten oder manuell.
  </Card>
  <Card title="Konfiguration" icon="Settings" href="/de/guide/configuration">
    Konfiguriere Routen, API-Referenz, Metadaten und Ausgabe.
  </Card>
  <Card title="Lokale Komponenten" icon="Code">
    Importiere Komponenten aus dem Projekt oder einem installierten Paket.
  </Card>
  <Card
    title="Quellcode"
    icon={<Github size={20} />}
    href="https://github.com/sebastian-software/ardo"
  >
    Lies die Implementierung und trage Änderungen auf GitHub bei.
  </Card>
</CardGroup>

```mdx
<CardGroup cols={2}>
  <Card title="Getting Started" icon="Rocket" href="/guide/getting-started">
    Set up a documentation site.
  </Card>
  <Card title="Local components" icon="Code">
    Import components into your MDX routes.
  </Card>
</CardGroup>
```

| Komponente  | Prop        | Typ                   | Zweck                                                             |
| ----------- | ----------- | --------------------- | ----------------------------------------------------------------- |
| `CardGroup` | `cols`      | `1 \| 2 \| 3 \| 4`    | Bevorzugte Spaltenzahl auf breiten Bildschirmen. Standard: `2`.   |
| `CardGroup` | `children`  | `ReactNode`           | Karten im responsiven Raster.                                     |
| `Card`      | `title`     | `string`              | Erforderlicher Kartentitel.                                       |
| `Card`      | `href`      | `string`              | Optionales internes oder externes Ziel. Macht die Karte klickbar. |
| `Card`      | `icon`      | `string \| ReactNode` | Registrierter Iconname oder React-Inhalt.                         |
| `Card`      | `children`  | `ReactNode`           | Karteninhalt.                                                     |
| `Card`      | `className` | `string`              | Zusätzliche CSS-Klasse.                                           |

## Tabs {#tabs}

Tabs eignen sich für gleichwertige Alternativen wie Paketmanager. Wähle einen Tab oder fokussiere ihn und nutze Links, Rechts, Pos1 und Ende.

      <Tab value="pnpm">pnpm</Tab>
      <Tab value="npm">npm</Tab>
      <Tab value="yarn">yarn</Tab>
    </TabList>
    <TabPanels>
      <TabPanel value="pnpm">
        <CodeBlock language="bash" code="pnpm add ardo" />
      </TabPanel>
      <TabPanel value="npm">
        <CodeBlock language="bash" code="npm install ardo" />
      </TabPanel>
      <TabPanel value="yarn">
        <CodeBlock language="bash" code="yarn add ardo" />
      </TabPanel>
    </TabPanels>
  </Tabs>
</GalleryPreview>

```mdx
<Tabs defaultValue="pnpm">
  <TabList>
    <Tab value="pnpm">pnpm</Tab>
    <Tab value="npm">npm</Tab>
  </TabList>
  <TabPanels>
    <TabPanel value="pnpm">pnpm add ardo</TabPanel>
    <TabPanel value="npm">npm install ardo</TabPanel>
  </TabPanels>
</Tabs>
```

Bei Komponenten, die Tabs intern erzeugen, setze `defaultValue` auf `Tabs` und passende explizite `value`-Werte auf Tab und Panel.

| Komponente | Prop           | Typ         | Zweck                                                                    |
| ---------- | -------------- | ----------- | ------------------------------------------------------------------------ |
| `Tabs`     | `defaultValue` | `string`    | Anfangs aktiver Tab. Standard: erster Tab.                               |
| `Tabs`     | `children`     | `ReactNode` | `TabList` und passende `TabPanels`.                                      |
| `Tab`      | `value`        | `string`    | Stabiler Wert passend zum `TabPanel`. Bei stabiler Reihenfolge optional. |
| `Tab`      | `children`     | `ReactNode` | Beschriftung des Tabs.                                                   |
| `TabPanel` | `value`        | `string`    | Passender Wert des Inhalts. Bei gleicher Reihenfolge optional.           |
| `TabPanel` | `children`     | `ReactNode` | Inhalt des Panels.                                                       |

## Codeblöcke {#code-blocks}

Die Kopiertaste übernimmt Code ohne Titel und Zeilennummern. Markdown-Codeblöcke werden beim Build hervorgehoben; `CodeBlock` akzeptiert auch direkt einen String.

<GalleryPreview id="gallery-code" label="Codebeispiel">
  <CodeBlock language="bash" title="terminal" code="pnpm add ardo" />
</GalleryPreview>

```mdx
<CodeBlock language="bash" title="terminal" code="pnpm add ardo" />
```

`CodeGroup` bündelt zusammengehörige Beispiele mit eigenen Dateinamen:

<GalleryPreview id="gallery-code-group" label="Codegruppen-Beispiel">
  <CodeGroup labels="Konfiguration,Startroute">
    <CodeBlock
      language="typescript"
      title="ardo.config.ts"
      code={
        'import { defineArdoConfig } from "ardo/config"\n\nexport default defineArdoConfig({ title: "My docs" })'
      }
    />
    <CodeBlock
      language="markdown"
      title="app/routes/home.md"
      code={"# Welcome\n\nStart with your first guide."}
    />
  </CodeGroup>
</GalleryPreview>

Markdown-Codeblöcke unterstützen Titel, markierte Zeilen, Zeilennummern und umbrechende Agenten-Prompts; siehe [Syntaxhervorhebung](/de/guide/markdown#syntax-highlighting).

### In TSX-Routen {#in-tsx-routes}

`ArdoCodeBlock` funktioniert direkt in `.tsx`-Routen. Schreibe Code als Kinder ohne Template-Literale oder besondere Escape-Zeichen:

```tsx
import { ArdoCodeBlock } from "ardo/ui"

export default function MyPage() {
  return (
    <ArdoCodeBlock language="tsx">
      export function Hello() {
        return <div>Hello world!</div>
      }
    </ArdoCodeBlock>
  )
}
```

Das Vite-Plugin `ardo:codeblock-highlight` verarbeitet ArdoCodeBlock **vor dem JSX-Parser**. Der Inhalt darf deshalb `<`, `{`, `>` und andere Syntax enthalten. Gemeinsame Einrückung wird entfernt.

Auch die `code`-Prop und Template-Literale als Kinder funktionieren:

```tsx
<ArdoCodeBlock code="const x = 42" language="typescript" />
```

Ist `language` dynamisch, entfällt die Build-Hervorhebung und der Code erscheint als Klartext.

## Icons {#icons}

Ardo enthält 50 [Streamline Core Line](https://streamlinehq.com/icons/core-line)-Icons für Inhalte. Sie nutzen dasselbe 14×14-Raster, runde Konturen und `currentColor` wie Seitenleiste und Kopfzeile.

Die registrierten Icons erscheinen hier mit 14 und 28 Pixeln. Nutze den Namen mit `Icon` oder importiere die Komponente aus `ardo/icons`.

<GalleryIcons />

### In MDX verwenden {#use-in-mdx}

Alle 50 Core-Icons stehen automatisch ohne Import oder Registrierung bereit:

```mdx
<Icon name="Zap" size={20} />
<Card title="Deploy your site" icon="Rocket">
  Build the static output and publish it to your host.
</Card>
```

| Komponente | Prop      | Typ                            | Zweck                                                |
| ---------- | --------- | ------------------------------ | ---------------------------------------------------- |
| `Icon`     | `name`    | `string`                       | Registrierter Iconname.                              |
| `Icon`     | `size`    | `number`                       | Optionale Darstellungsgröße.                         |
| `Icon`     | SVG props | `SVGAttributes<SVGSVGElement>` | Werden an die registrierte SVG-Komponente übergeben. |

### In React verwenden {#use-in-react}

```tsx
import { BookOpen, Rocket, ShieldCheck } from "ardo/icons"

<BookOpen size={20} />
<Rocket size={28} className="launch-icon" />
<ShieldCheck size={20} aria-label="Security checks passed" />
```

Die Standardgröße ist 24 px. `size` akzeptiert Zahlen und CSS-Längen; alternativ setzt du `width` und `height`. Icons erben die Textfarbe und sind standardmäßig dekorativ. Nutze `aria-label` oder `aria-labelledby`, wenn sie ohne Text Informationen vermitteln.

`ArdoIcon` rendert registrierte Icons anhand ihres Namens, etwa in einem Link:

```tsx
import { ArdoIcon, ArdoLink } from "ardo/ui"

export function LaunchLink() {
  return (
    <ArdoLink to="/guide/getting-started">
      <ArdoIcon name="Rocket" aria-hidden /> Get started
    </ArdoLink>
  )
}
```

### Icons hinzufügen oder ersetzen {#add-or-override-icons}

Mit `registerIcons()` in `app/root.tsx` registrierst du weitere SVG-React-Komponenten und Markenicons:

```tsx
import { Github } from "ardo/icons"
import { registerIcons } from "ardo/ui"

registerIcons({ Github })
```

Danach funktioniert `<Icon name="Github" />` in MDX. Ein vorhandener Name ersetzt das integrierte Icon. Andere Iconbibliotheken müssen direkte Abhängigkeiten sein und im Registrierungsmodul importiert werden.

`getRegisteredIconNames()` liefert integrierte und eigene Namen zur Validierung von Konfiguration.

## Layout und Navigation {#layout-and-navigation}

Diese Seite zeigt das echte Layout mit Kopfzeile, Abschnittswechsel, Seitenleiste, Breadcrumbs, Artikel, Inhaltsverzeichnis, Seitenaktionen und Fußzeile. Öffne auf schmalen Bildschirmen Menü und Inhaltsverzeichnis. Teste Suche und Theme direkt in der Kopfzeile.

[Layout und Navigation](/de/guide/layout-and-navigation) zeigt die Komposition, [Theming](/de/guide/theming) die Farben. Alle Beispiele übernehmen Änderungen ohne separates Vorschau-Theme.
