# Releases

Ardo veröffentlicht Framework, UI und Runtime als ein Paket. Diese Seite trennt verfügbare Funktionen von experimentellen und geplanten. Alle Änderungen stehen im [Changelog](https://github.com/sebastian-software/ardo/blob/main/packages/ardo/CHANGELOG.md).

## Upgrade-Anleitungen {#upgrade-guides}

- [Upgrade auf Ardo 6](/de/guide/releases/upgrade-to-v6) von Ardo 5: statischer Build ohne React Router und weniger Anwendungsdateien.
- [Upgrade auf Ardo 5](/de/guide/releases/upgrade-to-v5) von Ardo 4: Ferromark für Markdown/MDX und Ferriki für Hervorhebung.
- [Upgrade auf Ardo 4.0](/de/guide/releases/upgrade-to-v4) von Ardo 3: stabile Hauptversions-URLs.
- [TypeDoc-Migration](/de/guide/releases/migrate-from-typedoc): native API-Dokumentation ersetzt `typedoc`.

Coding-Agenten nutzen dieselben Anleitungen über die [Agentenanweisungen](/de/guide/agent-instructions).

## Verfügbar {#shipped}

Diese Funktionen liefert die aktuelle Paketlinie.

| Bereich             | Hinweise                                                                                                                   |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Statischer Build    | Vite mit HTML pro Seite, dateibasierten Routen und ohne Clientrouter.                                                      |
| Markdown und MDX    | Markdown, MDX, GFM, Frontmatter, Inhaltsverzeichnis und Standardkomponenten.                                               |
| Syntaxhervorhebung  | Ferriki beim Build für Markdown-Code und statische `CodeBlock`-Nutzung.                                                    |
| Suche               | Generierte Suchdaten und integrierte Oberfläche.                                                                           |
| Native API-Referenz | TypeScript-APIs über `api` in `ardo.config.ts`.                                                                            |
| Content-Sammlungen  | Schemavalidierte lokale Dateien als Routen und typisierte Datensätze für React.                                            |
| Social-Metadaten    | Kanonische URLs, Open Graph und Twitter für Markdown-Routen.                                                               |
| SEO-Ausgaben        | Sitemap, robots, LLM-Texte, Linkprüfung und Weiterleitungen.                                                               |
| Theme-Farben        | Marken-, Akzent- und Neutralfarben aus Konfiguration oder CSS.                                                             |
| Komponenten         | Callouts, Badges, Karten, Tabs, Akkordeons, Schritte, Code, Icons, Hero und Features: [Komponenten](/de/guide/components). |

## Experimentell {#experimental}

Diese Bereiche funktionieren, ihre API oder Wartung kann sich aber noch verändern.

| Bereich                 | Hinweise                                                                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Natives Compiler-SDK    | Festes TypeScript-7.1-Nightly; Kompatibilität und API-Stabilität brauchen Aufmerksamkeit.                                                                                         |
| Theme-Tokens            | CSS-Variablen und Vanilla-Extract-Tokens sind öffentlich; weitere Anpassungs-APIs können sich ändern.                                                                             |
| Dokumentationsversionen | Statische Versionsordner, Root-Weiterleitungen, `versions.json`, Umschalter und Altversionsbanner.                                                                                |
| Statisches i18n         | Vollständige Sprachbäume, lokalisierte Suche und UI-Texte, Sprachalternativen und Buildfehler bei fehlender Übersetzung: [Internationalisierung](/de/guide/internationalization). |
| Statisches OpenAPI      | Lokale OpenAPI-3.0/3.1-Referenzen aus JSON/YAML; kein interaktiver Playground.                                                                                                    |

## Nicht geplant {#not-planned}

Ardo konzentriert sich bewusst auf einen bestimmten Dokumentationsansatz.

| Bereich                        | Grund                                                                                                             |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| Gehostete Bearbeitung          | Ardo bleibt repositorybasiert und selbst gehostet. Für gehostete Zusammenarbeit passen entsprechende Plattformen. |
| Eigenes Analyticsprodukt       | Statische Websites können Anbieter direkt integrieren; Ardo muss keine Ereignisse speichern.                      |
| Minimal-JavaScript-Textwebsite | React-Wiederverwendung hat Vorrang. Für reine Texte können Astro, VitePress oder Starlight besser passen.         |
| TypeScript-Hoverbeispiele      | Twoslash-artige Hinweise bringen im Verhältnis viel Wartung und Tooling mit.                                      |
| Live-Playgrounds               | Sandpack-artige Editoren passen nicht zu statischer Ausgabe und kleinen Bundles.                                  |
