# Upgrade auf Ardo 6

Ardo 6 baut statische Websites nur mit Vite. `react-router` und `@react-router/dev` entfallen; es gibt keinen Clientrouter. Jede Seite wird beim Build zu HTML. Links laden das nächste vorgerenderte Dokument, das anschließend hydriert.

Die Migration entfernt vor allem Dateien. Routen unter `app/routes/`, Root-Komponente und Ardo-Konfiguration bleiben. Hintergründe stehen in [ADR 0020](https://github.com/sebastian-software/ardo/blob/main/docs/adr/0020-static-site-without-react-router.md). Bei bisherigem `typedoc` folge zusätzlich der [TypeDoc-Migration](/de/guide/releases/migrate-from-typedoc).

## So funktioniert der Build {#how-the-build-works-now}

- `ardo build` ruft Vites Builder-API im selben Prozess auf, baut Client und Server und rendert Routen nach `build/client/<route>/index.html`. Mit Versionierung liegen sie etwa unter `build/client/v6/`. Es schreibt `404.html` und prüft interne Links und Anker.
- `ardo dev` nutzt Vite mit Ardos Serverrendering-Middleware und liefert dasselbe Dokument wie der Build.
- `ardo preview` dient als statischer Host: `/guide` liefert `guide/index.html`; unbekannte Pfade erhalten die nächste `404.html`.

Nutze diese drei Befehle weiter. `react-router build` und `react-router dev` entfallen.

## Entfallene Dateien löschen {#delete-the-removed-files}

Lösche diese Dateien; ihre Aufgaben übernimmt Ardo:

| Datei                    | Ersatz                                                     |
| ------------------------ | ---------------------------------------------------------- |
| `react-router.config.ts` | Prerendering immer aktiv; Basispfad in Ardo-Konfiguration. |
| `app/entry.server.tsx`   | Ardos Serverrenderer; `ardo/entry.server` entfällt.        |
| `app/entry.client.tsx`   | Ardos Client-Einstiegspunkt hydriert jede Seite.           |
| `app/routes.ts`          | Virtuelle Routentabelle aus `app/routes/`.                 |
| `.react-router/`         | Entfernen, auch aus `.gitignore` und `tsconfig.json`.      |

Entferne direkte Abhängigkeiten auf `react-router`, `@react-router/dev`, `@react-router/node` und `isbot`. Ardo verwaltet React, React DOM und Vite selbst. Entferne `.react-router/types` aus `include` oder `rootDirs` in `tsconfig.json`.

Verschiebe Provider in die Root-Komponente und Dokumentmarkup in `Layout` (siehe unten). Für anfragespezifischen Serverkontext exportiere `withRenderContext` aus `app/server.ts`. [Internationalisierung](/de/guide/internationalization) zeigt isolierte gleichzeitige Palamedes-Renderings.

## Inhaltsicons aktualisieren {#update-content-icons}

`ardo/icons` exportiert eine Auswahl Streamline Core Line statt einer ganzen Bibliothek. Der [Katalog](/de/guide/components#icons) zeigt alle 50 Core-Exporte. Marken wie `Github` bleiben.

Alle 50 Icons sind automatisch registriert. Entferne ihre Imports und `registerIcons()` aus `app/root.tsx`; behalte nur eigene Registrierungen. Ersetze `Code2` durch `Code`, auch in `<Icon name="Code" />` und `<Card icon="Code">`.

Die Komponenten akzeptieren `size`, `className` und SVG-Attribute. Entferne die alte Iconabhängigkeit, wenn ungenutzt. Weitere Bibliotheken installierst und registrierst du explizit. Der [Katalog](/de/guide/components#icons) beschreibt Motive und Nutzungsbedingungen.

## `app/root.tsx` aktualisieren {#update-app-root-tsx}

Der Standardexport bleibt die Root-Komponente. `<ArdoRoot>` liest Konfiguration und generiert die Seitenleiste selbst. `config`-Prop, `virtual:ardo/config` und `ardo/ui/styles.css` können weg. Drei optionale Exporte bleiben:

- `meta`: `ArdoMetaFunction` aus `ardo/runtime`, ohne Argumente, mit bisherigen Deskriptoren wie `{ title: "My Docs" }`. Entfällt bei reinem Website-Titel; ohne `title` gilt die Konfiguration.
- `Layout`: HTML-Hülle, nur auf dem Server. Ohne Export gilt `ArdoRootLayout` aus `ardo/ui`; meist kannst du sie löschen.
- `ErrorBoundary`: bei fehlenden Seiten innerhalb der Root, bei Renderfehlern anstelle der Root. Standard ist `ArdoErrorBoundary`.

Vorher:

```tsx
import type { ReactNode } from "ardo/react"
import type { MetaFunction } from "ardo/router"
import { ArdoFooter, ArdoHeader, ArdoRoot, ArdoRootLayout, ArdoSidebar } from "ardo/ui"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export const meta: MetaFunction = () => [{ title: "My Docs" }]

export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout>{children}</ArdoRootLayout>
}

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader />
      <ArdoSidebar />
      <ArdoFooter />
    </ArdoRoot>
  )
}
```

Nachher:

```tsx
import { ArdoRoot } from "ardo/ui"

export default function Root() {
  return <ArdoRoot />
}
```

Behalte `ArdoHeader`, `ArdoSidebar` oder `ArdoFooter` als Kinder bei eigenen Props. Ohne Kinder rendert `ArdoRoot` dieselben Standardteile.

Behalte `Layout` für `colorScheme`, `icon` oder `className` auf `ArdoRootLayout`. Die früheren Props `theme` und `favicon` heißen jetzt `colorScheme` und `icon`. Eigene Hüllen ersetzen `<Meta />`, `<Links />` und `<Scripts />` durch `<ArdoHead />` in `<head>` und `<ArdoScripts />` am Body-Ende aus `ardo/runtime`. Siehe [Layout](/de/guide/layout-and-navigation#layout-the-html-shell).

Routen behalten `meta` und `handle`, etwa `export const handle = { layout: "bare" }`.

## Theme nach `app/root.tsx` verschieben {#move-the-theme-into-app-root-tsx}

Ardo 6 gestaltet die Website in JSX. `brand` entfällt in der Konfiguration, ebenso `applyBrandTheme` und `createTheme` aus `ardo/theme`. Farben, `chroma` und Tokens gehören in `ArdoRoot`-`theme`, Logos und Favicons werden importierte Dateien mit Vite-Fingerprints. Verbliebenes `brand` erzeugt einen Fehler mit Verweis hierher.

Vorher:

```ts
// ardo.config.ts
export default defineArdoConfig({
  title: "My Docs",
  brand: { color: "blue", accent: "teal", neutral: "slate", logo: "./app/assets/logo.svg" },
  icons: { source: "./app/assets/icon.svg" },
})

// app/styles/brand.css.ts
applyBrandTheme({ primary: 240, chroma: { brand: 0.6 }, dark: { color: { bg: "#101010" } } })
```

Nachher:

```tsx
// app/root.tsx
import { ArdoRoot } from "ardo/ui"

import icon from "./assets/icon.svg"
import logo from "./assets/logo.svg"

export default function Root() {
  return (
    <ArdoRoot
      theme={{
        color: "blue",
        accent: "teal",
        neutral: "slate",
        chroma: { color: 0.6 },
        dark: { color: { bg: "#101010" } },
      }}
      logo={logo}
      icon={icon}
    />
  )
}
```

- `primary` und `secondary` aus `applyBrandTheme` werden `color` und `accent`; der Chroma-Schlüssel `brand` wird `color`.
- Gemeinsame Tokenüberschreibungen gehören in `tokens`, Farben meist in `light` und `dark`.
- `icons.source` entfällt. Ohne `icon` bleiben Eulenicons; `icons: false` deaktiviert sie weiterhin.
- `gray` und `slate` sind jetzt Grau und gedämpftes Blau statt des gesättigten Blaus aus Ardo 5.
- Die ungenutzten Variablen `--ardo-color-brandLight`, `accentLight`, `accentDark`, `accentSubtle`, `bgAlt` und `sidebarBorder` entfallen.
- `--ardo-font-familyHeading` folgt `--ardo-font-family`; neue Textschriften gelten auch für Überschriften.

[Theming](/de/guide/theming) beschreibt alle Props.

## `tsconfig.json` vereinfachen {#trim-tsconfig-json}

Ersetze Compileroptionen durch Ardos Preset. Es setzt JSX, `jsxImportSource: "ardo"`, `moduleResolution: "bundler"`, strikten Modus und Typdeklarationen:

```json
{
  "extends": "ardo/tsconfig",
  "include": ["app/**/*", "*.ts"]
}
```

## Router-Imports ersetzen {#replace-router-imports}

Browserwerte kommen aus `ardo/runtime` oder `ardo/ui`, nicht aus `ardo`, das Node-Code enthält. React-APIs bleiben in `ardo/react`, React-DOM-Unterpfade bestehen weiter.

| Ardo 5 (React Router)                           | Ardo 6                                                 |
| ----------------------------------------------- | ------------------------------------------------------ |
| `Link` from `ardo/router`                       | `ArdoLink` mit `to` und Ankerattributen                |
| `NavLink` from `ardo/router`                    | `ArdoActiveLink`, ergänzt `active` und `aria-current`` |
| `useLocation().pathname`                        | `useArdoPath()`, Seitenpfad ohne Basis                 |
| `useNavigate()`                                 | `navigateTo(href)`, volle Seitennavigation             |
| `useHref(to)`                                   | `useArdoHref(to)` or `resolveArdoHref(to, page)`       |
| `useMatches()` für `handle`-Daten               | `useArdoPage().handle`                                 |
| `useRouteError()` in einer Fehlergrenze         | `useArdoPage().error`                                  |
| `MetaFunction` from `ardo/router`               | `ArdoMetaFunction` and `ArdoMetaDescriptor`            |
| `MemoryRouter` in Tests und Vorschauen          | `ArdoPageProvider` mit `path` und optionalem `base`    |
| `<Meta />`, `<Links />`, `<Scripts />`          | `<ArdoHead />` and `<ArdoScripts />`                   |
| `ardo/router/dom`, `ardo/router/routes`         | Entfällt; Ardo liefert Clienteinstieg und Routen.      |
| `ardo/entry.server`                             | Entfällt. Lösche `app/entry.server.tsx`.               |
| `ReactRouterConfig` from `ardo/config`          | Entfällt. Lösche `react-router.config.ts`.             |
| `withArdoGitHubPages()`, `withArdoVersioning()` | `base` or `versioning` in Ardo-Konfiguration           |
| `githubPages` option, `detectGitHubBasename()`  | Entfällt. Für GitHub-Pages-Projekte: `base: "/repo/"`. |
| `ardoRoutesPlugin`                              | Entfällt. `ardo()` generiert die Routen.               |
| `defineConfig`, `loadConfig` from `ardo`        | Entfällt. Nutze `defineArdoConfig` aus `ardo/config`.  |
| `ardo/press.css`                                | Entfällt. Ardo lädt das Stylesheet selbst.             |

Außer `ArdoMetaFunction` und `ArdoMetaDescriptor` sind dies Werte aus `ardo/runtime`. `ArdoLink` und `ArdoActiveLink` gibt es auch in `ardo/ui`. Props mit React-Routers `To` akzeptieren jetzt `string`.

`ArdoLink` ergänzt den Basispfad und rendert `<a>`:

```tsx
import { ArdoLink, useArdoPath } from "ardo/runtime"

export function BackToGuide() {
  const path = useArdoPath()
  if (path.startsWith("/guide")) return null
  return <ArdoLink to="/guide/getting-started">Read the guide</ArdoLink>
}
```

In Tests und Vorschauen umschließt `ArdoPageProvider` Komponenten mit Seitenzugriff:

```tsx
import { ArdoPageProvider } from "ardo/runtime"

render(
  <ArdoPageProvider path="/guide/intro">
    <ComponentUnderTest />
  </ArdoPageProvider>
)
```

## Basispfad einmal konfigurieren {#configure-the-base-path-once}

Router-`basename` und Flatten-Schritt entfallen. Setze `base` in Ardo; es gilt für Assets, Links und Ausgabeordner:

- GitHub-Pages-Projekte: `base: "/repo/"`.
- Root-Deployments und eigene Domains: keine Angabe.
- Versionierte Dokumentation: `versioning`; Seiten etwa unter `build/client/v6/`, globale Dateien wie `versions.json` unter `build/client/`.

Vollständige Beispiele unter [Deployment](/de/guide/deployment).

## Routen-Loader ersetzen {#replace-route-loaders}

`loader` und `action` werden nicht unterstützt. Vorgerenderte Seiten brauchen ihre Daten beim Build. Liefere sie über ein kleines Vite-Plugin mit virtuellem Modul:

```ts
// vite.config.ts
import { defineConfig, type Plugin } from "ardo/vite"

function releaseFacts(): Plugin {
  const id = "virtual:docs/release-facts"
  return {
    name: "docs:release-facts",
    resolveId(source) {
      return source === id ? `\0${id}` : undefined
    },
    async load(source) {
      if (source !== `\0${id}`) return undefined
      const response = await fetch("https://registry.npmjs.org/ardo/latest")
      const { version } = await response.json()
      return `export default ${JSON.stringify({ version })}`
    },
  }
}

export default defineConfig({
  plugins: [releaseFacts()],
})
```

```tsx
// app/routes/releases.tsx
import facts from "virtual:docs/release-facts"

export default function Releases() {
  return <p>Latest release: {facts.version}</p>
}
```

Deklariere das Modul in `.d.ts`. Ardos npm-Statistik auf der Startseite nutzt dieses Muster. Server und hydrierender Client importieren so dieselben Daten.

## Verhaltensänderungen {#behavior-changes}

- **Frontmatter-Layout: `bare` oder `default`.** `doc`, `home` und `page` hatten keine Wirkung und erzeugen jetzt eine Warnung.
- **Jede Seite hat einen Titel.** Ohne eigenes `title` gilt der Website-Titel.
- **Keine Git-Remote-Erkennung.** `githubPages` und `detectGitHubBasename` entfallen. Setze `base` bei Unterpfaden; es gilt in Entwicklung und Build.
- **Volle Seitennavigation.** Jeder Link ist `<a>` und lädt ein neues Dokument. Clientzustand wie offene Suche bleibt nicht erhalten.
- **Abschließende Slashes.** Interne Seitenlinks enden mit `/`, etwa `/guide/intro/`, damit Hosts direkt `index.html` liefern. Dateilinks bleiben unverändert.
- **HTML-Linkprüfung.** Der Build prüft interne Ziele einschließlich Komponenten, generierter Seiten, Anker, Weiterleitungen und Versionen. Konfiguration: [`linkCheck`](/de/guide/configuration#linkcheck).
- **Verzögerte Suche.** Der Suchindex lädt beim ersten Suchfokus, pro Sprache getrennt.

## Performance {#performance}

Historischer Vergleich der rein englischen Ardo-Dokumentation vor dem viersprachigen Beispiel, M1 Ultra, warmer Build:

| Version                                 | `ardo build` |
| --------------------------------------- | ------------ |
| Ardo 5 mit React Router 8 vor PR #382   | 18–20 s      |
| Ardo 5 mit Buildkorrekturen aus PR #382 | etwa 10.5 s  |
| Ardo 6                                  | etwa 5.6 s   |

Früh geladenes JavaScript über alle damaligen Seiten sank von etwa 425 KB auf 379 KB gzip. Der verzögerte Suchindex ist darin nicht enthalten.

## Upgrade prüfen {#verify-the-upgrade}

Führe Typprüfung, Tests und `ardo build` aus. Der Build darf keine defekten internen Links melden. Öffne mit `ardo preview` mehrere Seiten, folge Links und prüfe die Browserkonsole auf Fehler.
