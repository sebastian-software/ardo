# Passer à Ardo 6

Ardo 6 construit des sites statiques avec Vite seul. `react-router` et `@react-router/dev` disparaissent, sans routeur client. Chaque page est rendue en HTML au build. Un lien charge le document prérendu suivant, qui s’hydrate ensuite.

La migration retire surtout des fichiers. Routes `app/routes/`, composant racine et configuration restent. Voir [ADR 0020](https://github.com/sebastian-software/ardo/blob/main/docs/adr/0020-static-site-without-react-router.md). Si vous utilisiez `typedoc`, suivez aussi [Migrer depuis TypeDoc](/fr/guide/releases/migrate-from-typedoc).

## Fonctionnement du build {#how-the-build-works-now}

- `ardo build` appelle le builder Vite dans le même processus, construit client et serveur et prérend les routes dans `build/client/<route>/index.html`, ou sous `build/client/v6/` avec les versions. Il écrit `404.html` et vérifie liens internes et ancres.
- `ardo dev` utilise Vite avec le middleware de rendu Ardo et sert le même document que le build.
- `ardo preview` agit comme un hébergeur statique : `/guide` sert `guide/index.html` ; les chemins inconnus reçoivent le `404.html` le plus proche.

Conservez ces trois commandes. `react-router build` et `react-router dev` disparaissent.

## Supprimer les anciens fichiers {#delete-the-removed-files}

Supprimez ces fichiers ; Ardo reprend leur rôle :

| Fichier                  | Remplacement                                            |
| ------------------------ | ------------------------------------------------------- |
| `react-router.config.ts` | Prérendu permanent ; base dans la configuration Ardo.   |
| `app/entry.server.tsx`   | Rendu serveur intégré ; `ardo/entry.server` disparaît.  |
| `app/entry.client.tsx`   | Entrée client intégrée pour hydrater les pages.         |
| `app/routes.ts`          | Table de routes virtuelle générée depuis `app/routes/`. |
| `.react-router/`         | À retirer aussi de `.gitignore` et `tsconfig.json`.     |

Retirez les dépendances directes `react-router`, `@react-router/dev`, `@react-router/node` et `isbot`. Ardo gère React, React DOM et Vite. Retirez `.react-router/types` d’`include` ou `rootDirs` dans `tsconfig.json`.

Déplacez les providers dans la racine et le document dans `Layout` (ci-dessous). Pour un contexte serveur par requête, exportez `withRenderContext` depuis `app/server.ts`. [Internationalisation](/fr/guide/internationalization) montre l’isolation des rendus concurrents avec Palamedes.

## Mettre à jour les icônes {#update-content-icons}

`ardo/icons` exporte une sélection Streamline Core Line plutôt qu’une bibliothèque entière. Le [catalogue](/fr/guide/components#icons) liste les 50 exports Core. Les marques comme `Github` restent.

Les 50 icônes sont enregistrées automatiquement. Retirez leurs imports et `registerIcons()` d’`app/root.tsx`, sauf pour les ajouts personnalisés. Remplacez `Code2` par `Code`, y compris `<Icon name="Code" />` et `<Card icon="Code">`.

Les composants acceptent `size`, `className` et les attributs SVG. Retirez l’ancienne dépendance si elle est inutilisée. Installez et enregistrez explicitement les autres bibliothèques. Le [catalogue](/fr/guide/components#icons) détaille motifs et conditions.

## Mettre à jour `app/root.tsx` {#update-app-root-tsx}

L’export par défaut reste la racine. `<ArdoRoot>` lit la configuration et génère la navigation. Retirez la prop `config`, `virtual:ardo/config` et `ardo/ui/styles.css`. Trois exports facultatifs restent :

- `meta` : `ArdoMetaFunction` d’`ardo/runtime`, sans argument, avec les mêmes descripteurs tels `{ title: "My Docs" }`. Inutile pour le seul titre du site, fourni par la configuration.
- `Layout` : shell HTML, serveur uniquement. Sans export, `ArdoRootLayout` d’`ardo/ui` s’applique ; vous pouvez généralement le retirer.
- `ErrorBoundary` : dans la racine pour une page absente, à sa place pour une erreur de rendu. Défaut : `ArdoErrorBoundary`.

Avant :

```tsx
import type { ReactNode } from "ardo/react"
import type { MetaFunction } from "ardo/router"
import { ArdoFooter, ArdoHeader, ArdoRoot, ArdoRootLayout, ArdoSidebar } from "ardo/ui"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export const meta: MetaFunction = () => [{ title: "My Docs" }]

export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout>{children}</ArdoRootLayout>
}

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader />
      <ArdoSidebar />
      <ArdoFooter />
    </ArdoRoot>
  )
}
```

Après :

```tsx
import { ArdoRoot } from "ardo/ui"

export default function Root() {
  return <ArdoRoot />
}
```

Gardez `ArdoHeader`, `ArdoSidebar` ou `ArdoFooter` comme enfants s’ils ont des props personnalisées. Sans enfants, `ArdoRoot` rend les mêmes éléments par défaut.

Gardez `Layout` pour `theme`, `favicon` ou `className`. Un shell personnalisé remplace `<Meta />`, `<Links />`, `<Scripts />` par `<ArdoHead />` dans `<head>` et `<ArdoScripts />` en fin de body, depuis `ardo/runtime`. Voir [Layout](/fr/guide/layout-and-navigation#layout-the-html-shell).

Les routes conservent `meta` et `handle`, par exemple `export const handle = { layout: "bare" }`.

## Simplifier `tsconfig.json` {#trim-tsconfig-json}

Remplacez les options par le préréglage Ardo : JSX, `jsxImportSource: "ardo"`, `moduleResolution: "bundler"`, mode strict et déclarations :

```json
{
  "extends": "ardo/tsconfig",
  "include": ["app/**/*", "*.ts"]
}
```

## Remplacer les imports du routeur {#replace-router-imports}

Importez les valeurs navigateur depuis `ardo/runtime` ou `ardo/ui`, pas `ardo` qui contient du code Node. React reste dans `ardo/react` et les sous-chemins React DOM subsistent.

| Ardo 5 (React Router)                           | Ardo 6                                                      |
| ----------------------------------------------- | ----------------------------------------------------------- |
| `Link` from `ardo/router`                       | `ArdoLink` avec `to` et attributs de lien                   |
| `NavLink` from `ardo/router`                    | `ArdoActiveLink`, ajoute `active` et `aria-current``        |
| `useLocation().pathname`                        | `useArdoPath()`, chemin de page sans base                   |
| `useNavigate()`                                 | `navigateTo(href)`, navigation complète                     |
| `useHref(to)`                                   | `useArdoHref(to)` or `resolveArdoHref(to, page)`            |
| `useMatches()` pour les données `handle`        | `useArdoPage().handle`                                      |
| `useRouteError()` dans une frontière d’erreur   | `useArdoPage().error`                                       |
| `MetaFunction` from `ardo/router`               | `ArdoMetaFunction` and `ArdoMetaDescriptor`                 |
| `MemoryRouter` dans tests et aperçus            | `ArdoPageProvider` avec `path` et `base` facultatif         |
| `<Meta />`, `<Links />`, `<Scripts />`          | `<ArdoHead />` and `<ArdoScripts />`                        |
| `ardo/router/dom`, `ardo/router/routes`         | Supprimé ; Ardo fournit entrée client et routes.            |
| `ardo/entry.server`                             | Supprimé. Retirez `app/entry.server.tsx`.                   |
| `ReactRouterConfig` from `ardo/config`          | Supprimé. Retirez `react-router.config.ts`.                 |
| `withArdoGitHubPages()`, `withArdoVersioning()` | `base` or `versioning` dans la configuration Ardo           |
| `githubPages` option, `detectGitHubBasename()`  | Supprimé. Pour les projets GitHub Pages : `base: "/repo/"`. |
| `ardoRoutesPlugin`                              | Supprimé. `ardo()` génère les routes.                       |
| `defineConfig`, `loadConfig` from `ardo`        | Supprimé. Utilisez `defineArdoConfig` d’`ardo/config`.      |
| `ardo/press.css`                                | Supprimé. Ardo charge ses styles.                           |

Hormis `ArdoMetaFunction` et `ArdoMetaDescriptor`, ce sont des valeurs d’`ardo/runtime`. `ArdoLink` et `ArdoActiveLink` existent aussi dans `ardo/ui`. Les props utilisant `To` acceptent désormais `string`.

`ArdoLink` ajoute la base et rend un `<a>` :

```tsx
import { ArdoLink, useArdoPath } from "ardo/runtime"

export function BackToGuide() {
  const path = useArdoPath()
  if (path.startsWith("/guide")) return null
  return <ArdoLink to="/guide/getting-started">Read the guide</ArdoLink>
}
```

Dans les tests et aperçus, entourez les composants lisant la page avec `ArdoPageProvider` :

```tsx
import { ArdoPageProvider } from "ardo/runtime"

render(
  <ArdoPageProvider path="/guide/intro">
    <ComponentUnderTest />
  </ArdoPageProvider>
)
```

## Configurer la base une seule fois {#configure-the-base-path-once}

`basename` et l’étape d’aplatissement disparaissent. Définissez `base` dans Ardo pour ressources, liens et dossiers :

- Projets GitHub Pages : `base: "/repo/"`.
- Racine et domaines personnalisés : rien à définir.
- Documentation versionnée : `versioning`, pages sous `build/client/v6/` et fichiers globaux comme `versions.json` sous `build/client/`.

Exemples complets dans [Déploiement](/fr/guide/deployment).

## Remplacer les loaders {#replace-route-loaders}

`loader` et `action` ne sont pas pris en charge. Les pages prérendues ont besoin de leurs données au build. Fournissez-les via un petit plugin Vite avec module virtuel :

```ts
// vite.config.ts
import { defineConfig, type Plugin } from "ardo/vite"

function releaseFacts(): Plugin {
  const id = "virtual:docs/release-facts"
  return {
    name: "docs:release-facts",
    resolveId(source) {
      return source === id ? `\0${id}` : undefined
    },
    async load(source) {
      if (source !== `\0${id}`) return undefined
      const response = await fetch("https://registry.npmjs.org/ardo/latest")
      const { version } = await response.json()
      return `export default ${JSON.stringify({ version })}`
    },
  }
}

export default defineConfig({
  plugins: [releaseFacts()],
})
```

```tsx
// app/routes/releases.tsx
import facts from "virtual:docs/release-facts"

export default function Releases() {
  return <p>Latest release: {facts.version}</p>
}
```

Déclarez le module dans un `.d.ts`. Les statistiques npm de l’accueil suivent ce modèle. Serveur et client d’hydratation importent ainsi les mêmes données.

## Changements de comportement {#behavior-changes}

- **Layout frontmatter : `bare` ou `default`.** `doc`, `home` et `page` étaient sans effet et produisent un avertissement.
- **Un titre par page.** Sans `title` propre, le titre du site s’applique.
- **Pas de détection du remote Git.** `githubPages` et `detectGitHubBasename` disparaissent. Définissez `base` pour les sous-chemins, en développement comme au build.
- **Navigation complète.** Chaque `<a>` charge un document neuf. L’état client, telle une recherche ouverte, est perdu.
- **Barres finales.** Les liens de pages finissent par `/`, comme `/guide/intro/`, pour servir directement `index.html`. Les liens de fichiers restent inchangés.
- **Vérification du HTML.** Le build vérifie les cibles internes, composants, pages générées, ancres, redirections et versions. Réglage : [`linkCheck`](/fr/guide/configuration#linkcheck).
- **Recherche différée.** L’index charge au premier focus de recherche, séparément par langue.

## Performances {#performance}

Référence historique du site anglais avant l’exemple quadrilingue, M1 Ultra, build à chaud :

| Version                                  | `ardo build`   |
| ---------------------------------------- | -------------- |
| Ardo 5 avec React Router 8 avant PR #382 | 18–20 s        |
| Ardo 5 avec corrections de PR #382       | environ 10.5 s |
| Ardo 6                                   | environ 5.6 s  |

Le JavaScript chargé immédiatement sur l’ensemble des pages d’alors est passé d’environ 425 à 379 Ko gzip. L’index différé n’est pas inclus.

## Vérifier la migration {#verify-the-upgrade}

Exécutez vérification des types, tests et `ardo build`. Aucun lien interne cassé ne doit être signalé. Avec `ardo preview`, ouvrez plusieurs pages, suivez les liens et vérifiez la console.
