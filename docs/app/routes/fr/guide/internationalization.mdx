Ce site est disponible en anglais, allemand, français et espagnol. Choisissez la langue dans l’en-tête ou le menu mobile. Ardo conserve la page, les paramètres de requête et le fragment lors du changement de langue.

## Routes statiques par langue {#static-language-routes}

Configurez les langues dans `ardo.config.ts` ou le plugin Vite `ardo()` :

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "My Docs",
  i18n: {
    defaultLocale: "en",
    locales: [
      { id: "en", label: "English" },
      { id: "de", label: "Deutsch" },
      { id: "fr", label: "Français" },
      { id: "es", label: "Español" },
    ],
  },
})
```

Placez les routes correspondantes sous `app/routes/en/`, `app/routes/de/`, `app/routes/fr/` et `app/routes/es/`. Gardez les mêmes slugs dans toutes les langues. Ardo exige une arborescence complète et signale les pages manquantes au build. Il ne remplace pas silencieusement le contenu par une autre langue.

Le déploiement V6 utilise `/v6/en/`, `/v6/de/`, `/v6/fr/` et `/v6/es/`. Les anciennes versions de documentation conservent leur langue et leurs URL d’origine.

## Interface, recherche et métadonnées {#ui-search-and-metadata}

Utilisez `useArdoLocale()` depuis `ardo/runtime` pour la langue active, y compris pendant le rendu serveur. Passez des libellés traduits à `<ArdoRoot labels={...}>` pour la navigation, la recherche, les encadrés, les boutons de copie et les actions de page. Ardo formate les dates de mise à jour selon la langue de la route.

La recherche charge uniquement l’index de la langue active lorsque le lecteur sélectionne le champ ou saisit une requête. Le HTML généré contient le bon `lang`, l’URL canonique et les liens vers les autres langues. Les identifiants du code et chemins d’import restent inchangés. La référence API provient des commentaires sources en anglais et l’indique dans chaque interface traduite.

## Une source MDX avec Palamedes {#one-mdx-source-with-palamedes}

Cet exemple est compilé par Palamedes à partir d’un seul fichier MDX anglais. Ses paragraphes et ses espaces réservés de texte enrichi viennent des catalogues ; le composant React reste intact :

<Welcome />

Palamedes et Ardo possèdent chacun un compilateur MDX complet. Ce site laisse Ardo compiler les routes de documentation afin que la coloration, les ancres de titres, le sommaire et la recherche partagent la même source. Il importe ce petit exemple avec `?palamedes` via un adaptateur Vite dédié, laissant Palamedes gérer ce module. Les composants sont importés explicitement, comme le demande le compilateur MDX de Palamedes.

Les routes de documentation sont rédigées en Markdown et MDX localisés. Les textes partagés de l’interface utilisent les macros Palamedes et les catalogues PO de `docs/app/i18n/`. Chaque document charge sa propre langue, sans envoyer les quatre catalogues à chaque lecteur.

## Contexte du rendu serveur {#server-render-context}

Un site peut exporter `withRenderContext` depuis `app/server.ts` pour définir un contexte autour du rendu complet d’une page. Ce module entre uniquement dans le bundle serveur. La résolution des métadonnées et les composants React suspendus s’exécutent dans le même contexte :

```ts
import type { ArdoServerRenderContext } from "ardo/runtime"
import { createServerI18nScope } from "@palamedes/runtime/server"

const scope = createServerI18nScope()

export async function withRenderContext({ path, render }: ArdoServerRenderContext) {
  const i18n = await loadI18n(path.split("/")[1] ?? "en")
  return scope.run(i18n, render)
}
```

Ici, `loadI18n` est le chargeur de catalogues du site. Utilisez une instance immuable par langue ou une nouvelle instance par requête. N’activez pas de langue mutable pour tout le processus : les rendus parallèles mélangeraient les langues. Dans le navigateur, chargez le catalogue du document et appelez `setClientI18n` avant l’hydratation.

## Maintenir les traductions {#maintain-translations}

Depuis la racine du dépôt :

```bash
pnpm --filter ardo-docs i18n:extract
pnpm --filter ardo-docs i18n:check
```

L’extraction met à jour les messages sources et conserve les traductions existantes. L’audit vérifie l’exhaustivité, la syntaxe ICU, les arguments de pluriel et les espaces réservés de texte enrichi. Mettez à jour chaque route localisée lorsque la source change, puis construisez le site et lancez les tests navigateur de changement de langue.
