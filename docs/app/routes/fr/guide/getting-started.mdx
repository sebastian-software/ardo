# Premiers pas

Donnez cette phrase à votre agent de développement, dans un dépôt neuf ou existant. Le lien le dirige vers les [instructions versionnées pour les agents](/fr/guide/agent-instructions). Il adapte l’[exemple Basic testé](/fr/guide/agent-instructions#the-basic-example) et indique le résultat du contrôle des types, des tests et du build. Vous relisez le résultat comme toute autre pull request.

<SetupPrompt>Installe Ardo dans ce dépôt en suivant https://ardo-docs.dev/llms.txt.</SetupPrompt>

Sans agent, suivez l’[installation manuelle](#manual-installation) ci-dessous.

## Prérequis {#prerequisites}

Vous aurez besoin de :

- [Node.js](https://nodejs.org/) 22.22.0 ou ultérieur
- Linux ou Windows sur x64/arm64, ou macOS sur Apple Silicon, avec les dépendances natives optionnelles activées
- [pnpm](https://pnpm.io/) (recommandé), npm ou yarn

## Structure du projet {#project-structure}

Voici un projet Ardo. Les fichiers sous `app/routes/` deviennent des pages, `app/root.tsx` contient l’interface du site et le reste relève de la configuration :

```text
my-docs/
├── app/
│   ├── routes/                  # Pages: .md, .mdx, and .tsx files
│   │   ├── guide/
│   │   │   └── getting-started.mdx
│   │   └── home.tsx             # Home page
│   └── root.tsx                 # Root component (header, sidebar, footer)
├── ardo.config.ts               # Optional site configuration
├── vite.config.ts               # Optional extra Vite plugins or settings
├── pnpm-workspace.yaml          # pnpm build-script allowlist, when using pnpm
├── tsconfig.json
└── package.json
```

## Installation manuelle {#manual-installation}

Ces étapes créent un nouveau projet de documentation. Dans un dépôt existant, placez-le dans son propre paquet ou répertoire : Ardo construit un site statique indépendant, sans partager le routeur ni les points d’entrée de votre application.

### 1. Créer un projet {#1-create-a-new-project}

```bash
mkdir my-docs
cd my-docs
pnpm init
```

### 2. Installer les dépendances {#2-install-dependencies}

```bash
pnpm add ardo@6
pnpm add -D typescript@6
```

TypeScript 6 ou ultérieur vérifie les types d’un site Ardo. La [documentation API](/fr/guide/api-documentation#installation) optionnelle nécessite une nightly TypeScript 7.1 épinglée ; utilisez-la lorsque vous ajoutez `api`.

### 3. Ajouter les scripts {#3-add-package-scripts}

Ardo gère React, React DOM et Vite comme ses propres dépendances. Sa CLI lance le serveur de développement, construit le site statique et prévisualise la sortie client générée :

```json
{
  "scripts": {
    "dev": "ardo dev",
    "build": "ardo build",
    "preview": "ardo preview"
  }
}
```

Avec pnpm, ajoutez une liste de scripts de build autorisés pour qu’esbuild puisse préparer la dépendance native de Vite :

```yaml
# pnpm-workspace.yaml
packages:
  - "."

allowBuilds:
  esbuild: true
```

### 4. Ajouter une configuration Ardo optionnelle {#4-add-optional-ardo-configuration}

Ardo fonctionne sans fichier de configuration. Ajoutez `ardo.config.ts` pour les métadonnées du site, le déploiement ou le contenu. Le thème, la navigation, la barre latérale et le pied de page se configurent dans les props JSX de `root.tsx` :

**`ardo.config.ts`** :

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "My Documentation",
  description: "My awesome documentation site",
})
```

Le site est servi à la racine du domaine. Pour un sous-chemin, par exemple un site de projet GitHub Pages, définissez `base`. Le guide de [déploiement](/fr/guide/deployment) couvre les hébergeurs.

Ajoutez `vite.config.ts` uniquement pour des plugins supplémentaires ou des paramètres propres à Vite. La CLI Ardo ajoute automatiquement son intégration ; il n’est donc pas nécessaire d’appeler `ardo()` dans votre configuration Vite.

### 5. Créer les fichiers de l’application {#5-create-app-files}

Outre le contenu, un projet Ardo ne nécessite qu’`app/root.tsx`. Son export par défaut est le composant racine. `<ArdoRoot />` suffit pour obtenir un site complet : en-tête avec recherche et sélecteur de thème, une section latérale par dossier de `app/routes/`, et pied de page. Ardo rend la structure HTML, génère la table des routes et fournit les points d’entrée client et serveur, la configuration et les styles.

**`app/root.tsx`** :

```tsx
import { ArdoRoot } from "ardo/ui"

export default function Root() {
  return <ArdoRoot />
}
```

Passez `ArdoHeader`, `ArdoSidebar` ou `ArdoFooter` en enfants pour personnaliser l’interface, par exemple pour ajouter un lien de navigation :

```tsx
import { ArdoHeader, ArdoNav, ArdoNavLink, ArdoRoot } from "ardo/ui"

export default function Root() {
  return (
    <ArdoRoot>
      <ArdoHeader>
        <ArdoNav>
          <ArdoNavLink to="/guide/getting-started">Guide</ArdoNavLink>
        </ArdoNav>
      </ArdoHeader>
    </ArdoRoot>
  )
}
```

[Mise en page et navigation](/fr/guide/layout-and-navigation) décrit les sections latérales, le pied de page et les exports optionnels `Layout` et `ErrorBoundary` de `root.tsx`.

**`tsconfig.json`** :

```json
{
  "extends": "ardo/tsconfig",
  "include": ["app/**/*", "*.ts"]
}
```

Le preset définit `jsx`, `jsxImportSource: "ardo"` et les déclarations Ardo. Les imports React, MDX et `virtual:` sont ainsi vérifiés sans autre configuration.

Importez les composants depuis `ardo/ui`, les API d’exécution comme `ArdoLink` et `useArdoPath` depuis `ardo/runtime`, et les hooks React depuis `ardo/react`. Ardo fournit React : le paquet de documentation n’a pas besoin de sa propre dépendance React.

### 6. Créer les premières pages {#6-create-your-first-pages}

Créez une page d’accueil pour donner une destination à l’URL racine et au logo de l’en-tête :

**`app/routes/home.tsx`** :

```tsx
import { ArdoHero } from "ardo/ui"

export default function HomePage() {
  return (
    <ArdoHero
      name="My Documentation"
      tagline="Guides and examples for your project."
      actions={[{ text: "Get started", link: "/guide/getting-started", theme: "brand" }]}
    />
  )
}
```

Ajoutez le guide auquel renvoient l’accueil, l’en-tête et la barre latérale :

**`app/routes/guide/getting-started.mdx`** :

```markdown
---
title: Getting Started
---

# Getting Started

Welcome to your documentation site!
```

Exécutez `pnpm dev` et ouvrez `http://localhost:5173`. Votre accueil devrait apparaître ; choisissez **Get started** pour ouvrir le guide.

<Tip>
  L’[exemple Basic](/fr/guide/agent-instructions#the-basic-example) reprend cette installation avec
  un guide Markdown et un petit composant React, testés à chaque modification.
</Tip>

## Développement {#development}

Lancez le serveur de développement :

```bash
pnpm dev
```

Votre site fonctionne sur `http://localhost:5173`. Le serveur Vite prend en charge les modifications des routes MDX et TSX.

## Build de production {#production-build}

Lorsque vous êtes prêt à publier :

```bash
pnpm build
```

La sortie se trouve dans `build/client/` : un `index.html` prérendu par page, une `404.html` et les ressources avec empreinte de contenu, prêts pour tout hébergeur statique. Le build doit annoncer deux pages prérendues et aucun lien interne cassé. Il vérifie chaque lien et ancre du HTML généré. Prévisualisez le site localement avant de le déployer :

```bash
pnpm preview
```

## Étapes suivantes {#next-steps}

Votre site fonctionne. Personnalisez-le :

- Ajoutez pages, sections latérales, logo et liens d’en-tête avec [Mise en page et navigation](/fr/guide/layout-and-navigation#common-tasks)
- Enrichissez vos contenus avec [Markdown et MDX](/fr/guide/markdown) et les [composants](/fr/guide/components) intégrés
- Modifiez couleurs et styles avec les [thèmes](/fr/guide/theming), dont [Tailwind CSS](/fr/guide/theming#tailwind-css) en option
- [Déployez votre site](/fr/guide/deployment) sur GitHub Pages, Netlify, Vercel ou tout hébergeur statique
- Générez des pages de référence avec la [documentation API](/fr/guide/api-documentation)
