# Upgrade to Ardo 6

Ardo 6 builds static sites with Vite alone. It no longer uses React Router: neither `react-router` nor `@react-router/dev` is part of the toolchain, and there is no client-side router. Ardo renders every page to HTML at build time, and each link loads the next prerendered document, which then hydrates.

Most of the migration removes files rather than rewriting them. Your routes in `app/routes/`, your root component, and your Ardo configuration stay. The background is recorded in [ADR 0020](https://github.com/sebastian-software/ardo/blob/main/docs/adr/0020-static-site-without-react-router.md).

## How the build works now

- `ardo build` runs Vite's builder API in-process. It builds the client and the server bundle, prerenders every route to `build/client/<base path>/<route>/index.html`, writes `404.html`, and checks every internal link and anchor in the finished HTML.
- `ardo dev` runs a Vite dev server with Ardo's server-rendering middleware. It serves the same document the build would write.
- `ardo preview` serves the built output like a static host: `/guide` serves `guide/index.html`, and unknown paths get the nearest `404.html`.

Keep using the three commands. Do not call `react-router build` or `react-router dev`; those CLIs are gone from the project.

## Delete the removed files

Delete these files. Ardo now provides what they did:

| File                     | Replacement                                                            |
| ------------------------ | ---------------------------------------------------------------------- |
| `react-router.config.ts` | Prerendering is always on. Base path settings live in Ardo config.     |
| `app/entry.server.tsx`   | Ardo's built-in server renderer. `ardo/entry.server` no longer exists. |
| `app/entry.client.tsx`   | Ardo's built-in client entry, which hydrates every page.               |
| `app/routes.ts`          | A virtual route table that Ardo generates from `app/routes/`.          |
| `.react-router/`         | Nothing. Remove it from `.gitignore` and from `tsconfig.json`.         |

Also remove `react-router`, `@react-router/dev`, `@react-router/node`, and `isbot` from `package.json` if the project declared them. Ardo manages React, React DOM, Vite, and lucide-react as its own dependencies. If `tsconfig.json` lists `.react-router/types` in `include` or `rootDirs`, remove it.

Customized entry files have no direct replacement. Move provider setup into the root component, and move document-level markup into a `Layout` export (see below).

## Update `app/root.tsx`

The default export stays the root component, typically `<ArdoRoot config={config}>` with the header, sidebar, and footer as children. Three optional exports remain:

- `meta`: typed as `ArdoMetaFunction` from `ardo/runtime`. It takes no arguments and returns the same descriptor objects as before, such as `{ title: "My Docs" }`.
- `Layout`: the HTML shell. It now renders on the server only. Ardo uses `ArdoRootLayout` from `ardo/ui` when you omit it, so most projects delete their `Layout` export.
- `ErrorBoundary`: replaces the root on 404 and error pages. Ardo uses `ArdoErrorBoundary` when you omit it.

Before:

```tsx
import type { ReactNode } from "ardo/react"
import type { MetaFunction } from "ardo/router"
import { ArdoFooter, ArdoHeader, ArdoRoot, ArdoRootLayout, ArdoSidebar } from "ardo/ui"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export const meta: MetaFunction = () => [{ title: "My Docs" }]

export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout>{children}</ArdoRootLayout>
}

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader />
      <ArdoSidebar />
      <ArdoFooter />
    </ArdoRoot>
  )
}
```

After:

```tsx
import type { ArdoMetaFunction } from "ardo/runtime"
import { ArdoFooter, ArdoHeader, ArdoRoot, ArdoSidebar } from "ardo/ui"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export const meta: ArdoMetaFunction = () => [{ title: "My Docs" }]

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader />
      <ArdoSidebar />
      <ArdoFooter />
    </ArdoRoot>
  )
}
```

Keep a `Layout` export when it passes options such as `theme`, `favicon`, or `className` to `ArdoRootLayout`. A fully custom shell replaces React Router's `<Meta />`, `<Links />`, and `<Scripts />` with `<ArdoHead />` in `<head>` and `<ArdoScripts />` at the end of `<body>`, both from `ardo/runtime`. See [Site UI](/guide/site-ui#layout-the-html-shell).

Route modules keep their `meta` and `handle` exports, for example `export const handle = { layout: "bare" }`.

## Replace router imports

Import runtime values from `ardo/runtime` or `ardo/ui`. Do not import them from the package root `ardo` in browser code: that entry also contains Node-only build code. React APIs still come from `ardo/react`, and the `ardo/react-dom/*` subpaths still exist.

| Ardo 5 (React Router)                           | Ardo 6                                                   |
| ----------------------------------------------- | -------------------------------------------------------- |
| `Link` from `ardo/router`                       | `ArdoLink` with `to` and anchor attributes               |
| `NavLink` from `ardo/router`                    | `ArdoActiveLink`, which adds `active` and `aria-current` |
| `useLocation().pathname`                        | `useArdoPath()`, the page path without the base path     |
| `useNavigate()`                                 | `navigateTo(href)`, a full page navigation               |
| `useHref(to)`                                   | `useArdoHref(to)` or `resolveArdoHref(to, page)`         |
| `useMatches()` for route `handle` data          | `useArdoPage().handle`                                   |
| `useRouteError()` in an error boundary          | `useArdoPage().error`                                    |
| `MetaFunction` from `ardo/router`               | `ArdoMetaFunction` and `ArdoMetaDescriptor`              |
| `MemoryRouter` in tests and Storybook           | `ArdoPageProvider` with `path` and optional `base`       |
| `<Meta />`, `<Links />`, `<Scripts />`          | `<ArdoHead />` and `<ArdoScripts />`                     |
| `ardo/router/dom`, `ardo/router/routes`         | Removed. Ardo provides the client entry and route table. |
| `ardo/entry.server`                             | Removed. Delete `app/entry.server.tsx`.                  |
| `ReactRouterConfig` from `ardo/config`          | Removed. Delete `react-router.config.ts`.                |
| `withArdoGitHubPages()`, `withArdoVersioning()` | `githubPages`, `base`, or `versioning` in Ardo config    |
| `ardoRoutesPlugin`                              | Removed. The `ardo()` plugin generates the route table.  |

All of these, except `ArdoMetaFunction` and `ArdoMetaDescriptor`, are values exported from `ardo/runtime`. `ArdoLink` and `ArdoActiveLink` are also exported from `ardo/ui`. UI props that took React Router's `To` type now take a `string`.

`ArdoLink` adds the base path to internal targets and renders a plain `<a>`:

```tsx
import { ArdoLink, useArdoPath } from "ardo/runtime"

export function BackToGuide() {
  const path = useArdoPath()
  if (path.startsWith("/guide")) return null
  return <ArdoLink to="/guide/getting-started">Read the guide</ArdoLink>
}
```

In tests and stories, wrap components that read the current page in `ArdoPageProvider`:

```tsx
import { ArdoPageProvider } from "ardo/runtime"

render(
  <ArdoPageProvider path="/guide/intro">
    <ComponentUnderTest />
  </ArdoPageProvider>
)
```

## Configure the base path once

There is no separate router `basename` and no flatten step anymore. Set the base path in Ardo config, and Ardo applies it to assets, links, and the output folders:

- GitHub Pages project sites: keep `githubPages: true`, the default, which detects the repository name during the build, or set `base: "/repo/"`.
- Root deployments and custom domains: set `githubPages: false`.
- Versioned docs: use the `versioning` option. Ardo writes the current version's pages under its folder, such as `build/client/v6/`, and site-wide files such as `versions.json` at the top of `build/client/`.

See [Deployment](/guide/deployment) for complete examples.

## Replace route loaders

Route `loader` and `action` exports are not supported. Pages are prerendered, so data they need must be available at build time. Provide it through a small Vite plugin with a virtual module, and import that module from the page:

```ts
// vite.config.ts
import type { Plugin } from "vite"
import { defineConfig } from "ardo/vite"

function releaseFacts(): Plugin {
  const id = "virtual:docs/release-facts"
  return {
    name: "docs:release-facts",
    resolveId(source) {
      return source === id ? `\0${id}` : undefined
    },
    async load(source) {
      if (source !== `\0${id}`) return undefined
      const response = await fetch("https://registry.npmjs.org/ardo/latest")
      const { version } = await response.json()
      return `export default ${JSON.stringify({ version })}`
    },
  }
}

export default defineConfig({
  plugins: [releaseFacts()],
})
```

```tsx
// app/routes/releases.tsx
import facts from "virtual:docs/release-facts"

export default function Releases() {
  return <p>Latest release: {facts.version}</p>
}
```

Declare the module's type in a `.d.ts` file so TypeScript accepts the import. The Ardo docs site uses this pattern for the npm statistics on its home page. Because the prerendered HTML and the hydrating client import the same module, both see the same data.

## Behavior changes

- **Full page navigations.** Every link is a plain `<a>`, and each click loads a new prerendered document. Client state, such as an open search dialog, does not survive navigation.
- **Trailing slashes.** Ardo emits internal page links with a trailing slash, such as `/guide/intro/`, so static hosts serve each page's `index.html` without a redirect. Links to files such as `llms.txt` keep their form.
- **Link check on the built HTML.** `ardo build` always checks every internal link, image, script, stylesheet, and `#fragment` in the generated HTML, including links from components and generated pages. Configure it with [`linkCheck`](/guide/configuration#linkcheck).
- **Lazy search index.** The search index, about 75 KB gzip on the Ardo docs, loads when a reader first focuses search instead of with every page.

## Performance

Measured on the Ardo documentation site, M1 Ultra, warm build:

| Version                                    | `ardo build` |
| ------------------------------------------ | ------------ |
| Ardo 5 with React Router 8, before PR #382 | 18–20 s      |
| Ardo 5 with the build fixes from PR #382   | about 10.5 s |
| Ardo 6                                     | about 5.6 s  |

Eager client JavaScript across all pages dropped from about 425 KB to about 379 KB gzip. The lazy search index is not part of that number.

## Verify the upgrade

Run the project's typecheck and tests, then `ardo build`. The build should report no broken internal links. Open a few pages with `ardo preview`, follow links between them, and check that the browser console shows no hydration errors.
