# Component Gallery

Try the components that ship with Ardo. These examples use the same theme, styles, and React runtime as the rest of this site. Switch the theme in the header or resize the page to review them in context.

Authoring components such as `Tabs`, `Card`, and `Tip` are available in MDX without imports. In TSX, import their `Ardo`-prefixed equivalents from `ardo/ui`, such as `ArdoTabs` and `ArdoCard`. Landing-page components are imported explicitly, as shown below. See the [component inventory](/guide/component-inventory) for the full authoring baseline.

## Tabs

Use tabs for equivalent choices, such as package managers. Select a tab or focus it and use Left, Right, Home, and End to move through the choices.

## Accordions

Put optional explanations in an accordion. In a group with `onlyOneOpen`, opening an item closes its sibling. Space and Enter toggle the focused item; Up and Down move between triggers.

## Code and copying

Code blocks include a copy button that copies the code without the title or line numbers. Markdown fences are highlighted at build time; the `CodeBlock` component also accepts a string directly.

<GalleryPreview id="gallery-code" label="Code example">
  <CodeBlock language="bash" title="terminal" code="pnpm add ardo" />
</GalleryPreview>

```mdx
<CodeBlock language="bash" title="terminal" code="pnpm add ardo" />
```

Use `CodeGroup` for related snippets with their own file names:

<GalleryPreview id="gallery-code-group" label="Code group example">

      language="markdown"

The [Markdown guide](/guide/markdown#syntax-highlighting) covers highlighted lines, line numbers, and wrapped agent prompts.

## Callouts

Choose the variant that matches the information. All five use the site's theme tokens and support a custom title.

<Tip title="Keep related instructions together">
  Use a callout for a short piece of guidance that belongs next to the task.
</Tip>
<Info title="Static output">Ardo prerenders routes during the production build.</Info>
<Note title="Optional configuration">
  A route can use frontmatter to override its title and sidebar position.
</Note>
<Warning title="Check the destination">
  Review the deployment base path before publishing a versioned site.
</Warning>
<Danger title="Destructive example">
  Export your data before replacing a directory that contains work you need.
</Danger>

```mdx
<Tip title="Keep related instructions together">Put the guidance next to the task.</Tip>
```

The same variants are available as [GitHub-style alerts](/guide/markdown#github-style-alerts) in plain Markdown.

## Steps

## Layout and navigation

The page around these examples is the live layout example: header, section navigation, sidebar, breadcrumbs, article, outline, page actions, and footer. On a narrow screen, open the menu and the on-page outline. Use search and the theme toggle in the header to inspect their real behavior.

See [Site UI](/guide/site-ui) for composition examples and [Custom Theme](/guide/custom-theme) to change the palette. The examples inherit those changes without a separate preview theme.

## Work on a component

From the repository root, run `pnpm docs:dev` and open this route. Add or update the MDX example with the component change. Use `pnpm docs:build` to check static rendering and links, then `pnpm test:e2e` for browser interactions. The browser suite covers tabs, accordions, copying, themes, search, and responsive navigation; unit tests cover component logic and additional states.
