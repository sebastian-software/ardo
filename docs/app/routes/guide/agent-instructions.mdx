# Agent Instructions

These instructions cover Ardo 6. Use them for a new documentation site, an existing React repository, or an upgrade. Ardo 6 does not ship `create-ardo`.

## Match the Version First

Read the repository's manifest and lockfile to identify its installed Ardo version. For a new site, target Ardo 6 explicitly. Use `https://ardo-docs.dev/v6/llms.txt` as the documentation index and `https://ardo-docs.dev/v6/llms-full.txt` for the complete Markdown instructions. The unversioned text files follow the current documentation version and can change when another major is released.

Read the reference project from the matching `ardo-v<exact-version>` Git tag in [Ardo's repository](https://github.com/sebastian-software/ardo/tags). For example, Ardo `6.0.0` uses `ardo-v6.0.0`. Do not combine a released package with examples from `main`. During development, use the instructions, examples, and built package from the same checkout revision.

When upgrading from another major, read that major's documentation and the target major's migration guidance before changing configuration. If a matching release tag or instruction is unavailable, report the gap rather than guessing from a different version.

## Inspect the Repository

Check the package manager, workspace layout, Node.js version, dependency versions, Vite configuration, React Router configuration, application root, routes, styles, and deployment workflow. Ardo needs Node.js 22.13.0 or newer and a supported native target with optional dependencies enabled.

Choose the closest [reference project](/guide/reference-projects):

| Task                                                | Reference path in the matching Git tag |
| --------------------------------------------------- | -------------------------------------- |
| New site or product documentation in one React app  | `examples/basic`                       |
| TypeScript library with generated API documentation | `examples/library`                     |
| Documentation for multiple workspace packages       | `examples/monorepo`                    |
| Markdown owned outside the route tree               | `examples/content-sources`             |

Read the reference README, manifest, configuration, app entry files, and build test. Its contract identifies the authored source and generated files. References describe working project shapes; adapt them to the target repository.

## Make the Smallest Compatible Change

State the chosen reference, files to add or change, validation commands, and unresolved choices before editing. Follow the repository's instructions and the requested scope. Ask for direction when a necessary change affects existing application behavior or deployment ownership.

For a **new site**, adapt the basic reference into the requested directory. Replace `workspace:*` with an explicit released Ardo 6 dependency, retain compatible dependency versions from the selected tag, and use the chosen package manager's lockfile. Workspace references use `workspace:*` only inside Ardo's own repository. With pnpm, allow esbuild's build script as shown in [manual installation](/guide/getting-started#manual-installation); do not copy Ardo's entire workspace policy. Configure the site's title and authored routes, then adapt the deployment configuration to the requested host.

For an **existing project**, introduce Ardo around documentation routes. Merge the necessary dependencies and plugin configuration. Preserve customized root/layout code, providers, component systems, styles, routes, workspace policy, and deployment choices. See [Adopt Ardo in an Existing Project](/guide/adopt-ardo).

For an **upgrade**, update the dependency and documented integration changes. Compare the existing setup with the matching target reference. Preserve authored content and application-specific behavior; do not replace framework entry files wholesale.

`app/routes.ts`, generated API routes, and materialized collection routes are build output. Do not edit them by hand. Native API documentation is opt-in; add its native compiler alias, `oxc-parser` dependency, and API configuration only when the project needs it. Follow [Native API Documentation](/guide/api-documentation) for the matching dependency versions. Tailwind is optional; retain the repository's styling choice.

## Validate and Report

Install dependencies with the repository's package manager. Run its applicable typecheck and tests, then build the site. For an existing application, also run the checks that protect its existing routes. If a check is unavailable, say which behavior remains unverified.

Inspect the generated HTML for the home page and an authored documentation route. Verify generated API or collection pages when enabled. Start the local development server and check that navigation works and the browser reports no runtime errors. Build success alone does not establish that an existing application's integration is correct.

Report the files changed, dependency version, selected reference tag or checkout revision, validation results, and any remaining gaps. Do not deploy or change hosted-service ownership unless requested.

The reference projects are built and their output is checked by `pnpm test:integration` in Ardo's CI. The basic and library references also run as isolated consumers of the packed Ardo package, including a typecheck and production build. These checks validate the reference setup; they do not evaluate every agent's interpretation of these instructions.
