# Agent Instructions

These instructions cover Ardo 6. Use them for a new documentation site, an existing React repository, or an upgrade. Ardo 6 does not ship `create-ardo`.

## Match the Version First

Read the repository's manifest and lockfile to identify its installed Ardo version. For a new site, use the latest published release unless a version or major was requested; then select its matching documentation and Basic example. These instructions apply when that selected major is Ardo 6. For an existing site, retain the installed major unless the task includes an upgrade. Use `https://ardo-docs.dev/v6/llms.txt` as the documentation index and `https://ardo-docs.dev/v6/llms-full.txt` for the complete Markdown instructions. The unversioned text files follow the current documentation version and can change when another major is released.

Read `examples/basic` from the matching `ardo-v<exact-version>` Git tag in [Ardo's repository](https://github.com/sebastian-software/ardo/tags). For example, Ardo `6.0.0` uses `ardo-v6.0.0`. Do not combine a released package with examples from `main`. During development, use the instructions, examples, and built package from the same checkout revision.

When upgrading from another major, read that major's documentation and the target major's migration guidance before changing configuration. For Ardo 5, follow [Upgrade to Ardo 6](/guide/upgrade-to-v6). If a matching release tag or instruction is unavailable, report the gap rather than guessing from a different version.

## Inspect the Repository

Check the package manager, workspace layout, Node.js version, dependency versions, `ardo.config.*`, Vite configuration, application root, any framework or router configuration, routes, styles, and deployment workflow. Ardo needs Node.js 22.22.0 or newer and a supported native target with optional dependencies enabled.

Use the version-matched [Basic example](/guide/reference-projects) at
`examples/basic` as the shared application setup. Read its README, manifest,
configuration, and app files. Its README identifies the authored source,
generated files, and commands for both workspace and independent use.

Select optional features by the project's needs:

| Need                                                      | Configuration guide                                             |
| --------------------------------------------------------- | --------------------------------------------------------------- |
| API reference for one TypeScript project                  | [Native API Documentation](/guide/api-documentation)            |
| API reference for multiple packages                       | [Multiple packages](/guide/api-documentation#multiple-packages) |
| Markdown outside the route tree or static collection data | [Content Sources](/guide/content-sources)                       |
| Hosting and base-path settings                            | [Deployment](/guide/deployment)                                 |

A monorepo changes API inputs, not the documentation application's runtime
boundary. Declare and install the docs package's dependencies locally. Import
workspace components through an installed packaged dependency, not sibling
source paths. API generation can read separately configured TypeScript projects.

The [Ardo setup skill](https://github.com/sebastian-software/ardo/tree/main/skills/ardo) uses these versioned instructions and the same Basic example, then adds the selected feature configuration. Install that folder through your assistant's normal skill support. Keep setup rules here instead of maintaining separate skill templates.

## Make the Smallest Compatible Change

State the example revision, files to add or change, validation commands, and unresolved choices before editing. Follow the repository's instructions and the requested scope. Ask for direction when a necessary change affects existing application behavior or deployment ownership.

For a **new site**, adapt the basic reference into the requested directory. Replace `workspace:*` with an explicit released Ardo 6 dependency, let Ardo manage its React, React DOM, and Vite versions, and use the chosen package manager's lockfile. The workspace example uses `workspace:*` only inside Ardo's own repository. With pnpm, allow esbuild's build script as shown in [manual installation](/guide/getting-started#manual-installation); do not copy Ardo's entire workspace policy. Set a custom site title in optional `ardo.config.ts`, add the authored routes, then adapt the deployment configuration to the requested host.

For an **existing project**, introduce Ardo around documentation routes. Merge the necessary dependencies and move Ardo's options into optional `ardo.config.ts` with `defineArdoConfig` from `ardo/config`. Preserve custom Vite plugins and settings in `vite.config.ts`; the Ardo CLI adds its own framework integration without an `ardo()` plugin call. Preserve customized root/layout code, providers, component systems, styles, routes, workspace policy, and deployment choices. See [Adopt Ardo in an Existing Project](/guide/adopt-ardo).

For an **upgrade**, update the dependency and documented integration changes. Compare the existing setup with the matching target example. Preserve authored content and application-specific behavior; do not replace the root component or custom shell code wholesale. Delete only the files the [upgrade guide](/guide/upgrade-to-v6) lists as removed.

Generated API routes and materialized collection routes are build output, and the route table is a virtual module. Do not edit them by hand. Native API documentation is opt-in; add the pinned native TypeScript compiler, `oxc-parser` dependency, and API configuration only when the project needs it. Follow [Native API Documentation](/guide/api-documentation) for the matching dependency versions. Use `ardo dev`, `ardo build`, and `ardo preview` for the managed toolchain. Import React APIs from `ardo/react`, Ardo's runtime APIs such as `ArdoLink`, `useArdoPath`, and `ArdoMetaFunction` from `ardo/runtime`, components from `ardo/ui`, and Vite configuration helpers from `ardo/vite`. Never import runtime values from the package root `ardo` in browser code; that entry also contains Node-only build code. Set `jsxImportSource` to `ardo` and use `ardo/vite/client` in TypeScript's `types` list. The basic reference only requires Ardo at runtime; TypeScript remains a development tool.

Ardo 6 has no client-side router and no framework entry files. A project consists of `app/routes/**` (Markdown, MDX, and TSX routes), `app/root.tsx`, whose default export is the root component, and optional configuration. `root.tsx` may export `meta`, `ErrorBoundary`, and `Layout`; omit `Layout` unless the project needs a custom HTML shell, because Ardo renders `ArdoRootLayout` by default. Configure the base path once in Ardo config with `base` or `versioning`. Do not add `react-router.config.ts`, `app/entry.server.tsx`, `app/entry.client.tsx`, or a generated `app/routes.ts`, and do not import the removed `ardo/router`, `ardo/router/dom`, `ardo/router/routes`, `ardo/entry.server`, `ReactRouterConfig`, `withArdoGitHubPages`, or `withArdoVersioning` APIs. Route loaders and actions are not supported; provide build-time data through a Vite plugin with a virtual module. Tailwind is optional; retain the repository's styling choice.

## Validate and Report

Install dependencies with the repository's package manager. Run its applicable typecheck and tests, then build the site. For an existing application, also run the checks that protect its existing routes. If a check is unavailable, say which behavior remains unverified.

Inspect the generated HTML for the home page and an authored documentation route. Verify generated API or collection pages when enabled. Confirm that `ardo build` reports no broken internal links. Start the local development server and check that links load the expected pages and the browser reports no runtime errors. Build success alone does not establish that an existing application's integration is correct.

Report the files changed, dependency version, selected reference tag or checkout revision, validation results, and any remaining gaps. Do not deploy or change hosted-service ownership unless requested.

Ardo's CI runs `pnpm test:integration` against Basic and focused internal feature fixtures. Basic and its optional API configuration also install, typecheck, and build against the packed Ardo package outside the workspace. Browser checks cover development and preview. These checks validate the executable setup; they do not evaluate every agent's interpretation of these instructions.
