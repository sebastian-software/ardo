# Troubleshooting

Most Ardo issues come from the boundary between three systems: Vite build configuration, React Router routes, and Markdown/MDX content. Start with the section that matches the symptom, then verify the project still follows the scaffolded structure.

## Installation Issues

### `Cannot find module 'ardo'`

Make sure you have installed all required dependencies:

```bash
pnpm add ardo react react-dom react-router isbot
```

### Node.js Version Error

Ardo requires Node.js 22.13.0 or higher. Check your version:

```bash
node --version
```

If you need to upgrade, consider using [nvm](https://github.com/nvm-sh/nvm) or [fnm](https://github.com/Schniz/fnm).

## Build Issues

### `Failed to resolve import`

Ensure your `vite.config.ts` has the Ardo plugin configured:

```typescript
import { defineConfig } from "vite"
import { ardo } from "ardo/vite"

export default defineConfig({
  plugins: [ardo({/* config */})],
})
```

### TypeScript Errors in Routes

If you see type errors in generated route files, try:

1. Run `pnpm build` to regenerate route types
2. Restart your TypeScript server in your editor
3. Check that `tsconfig.json` includes React Router's generated route types and your `app` directory
4. Confirm the Ardo route generator is writing markdown routes into `app/routes`

### Build Fails with Memory Error

For large documentation sites, increase Node.js memory:

```bash
NODE_OPTIONS=--max-old-space-size=4096 pnpm build
```

## Development Issues

### Hot Reload Not Working

1. Check that you're editing files in the `app/routes/` directory
2. Ensure Vite dev server is running
3. Try restarting the dev server

### Styles Not Applied

Make sure you're importing the Ardo styles. If using a custom theme, verify your CSS imports.

### Search Not Working

Search is built at build time. In development:

1. Run `pnpm build` once to generate the search index
2. Restart the dev server

For production, the search index is automatically generated during build.

## Content Issues

### Markdown Not Rendering

Check that your file:

1. Has a `.md` or `.mdx` extension
2. Is located in the `app/routes/` directory
3. Has valid frontmatter (if using frontmatter)

### Code Blocks Not Highlighted

Syntax highlighting uses Ferriki. Ensure you specify the language:

````markdown
```javascript
const foo = "bar"
```
````

See [Ferriki's standard assets](https://github.com/sebastian-software/ferriki/blob/main/docs/ferriki-api.md#standard-assets) for supported languages and themes. An unknown language produces a warning and renders as plain text.

### Native Engine or Asset Loading Fails

Ardo requires Node.js 22.13 or newer and native binaries for Linux or Windows on x64/arm64, or macOS on Apple Silicon. Keep optional dependencies enabled when installing packages.

Ferriki downloads standard language and theme assets on first use. For offline CI, populate and persist a cache beforehand, then set `FERRIKI_CACHE_DIR` to its location and `FERRIKI_ASSETS_REMOTE=0` to disable downloads. A missing theme or native binary fails the build; see [Ferriki troubleshooting](https://github.com/sebastian-software/ferriki/blob/main/docs/troubleshooting.md).

### CodeBlock Not Highlighted in `.tsx` Routes

The `ardo:codeblock-highlight` plugin requires a **static** `language` prop. If the language is dynamic (from a variable or expression), build-time highlighting is skipped and the code renders as plain text.

Code can be provided as plain text children, template literal children, or via the `code` prop:

```tsx
<CodeBlock language="typescript">const x = 42</CodeBlock>
```

For fully dynamic code, use the `highlightCode` utility from `ardo/vite` at build time:

```typescript
import { highlightCode } from "ardo/vite"
const html = await highlightCode(dynamicCode, "typescript")
```

### Images Not Loading

Use relative paths from your markdown file:

```markdown
![Alt text](./images/screenshot.png)
```

Or absolute paths from the public directory:

```markdown
![Alt text](/images/screenshot.png)
```

## Deployment Issues

### 404 on Page Refresh

For static hosting (GitHub Pages, Netlify, etc.), ensure your hosting is configured for SPA routing, or use Ardo's static prerendering.

### Base Path Issues

If deploying to a subdirectory, set the `base` option in `vite.config.ts`:

```typescript
export default defineConfig({
  base: "/my-docs/",
  plugins: [ardo({/* config */})],
})
```

## Getting Help

If your issue isn't listed here:

1. Check the [GitHub Issues](https://github.com/sebastian-software/ardo/issues) for similar problems
2. Open a [GitHub Discussion](https://github.com/sebastian-software/ardo/discussions) for questions
3. Create a new issue with a minimal reproduction

### Native TSX highlighting and HTML compatibility

Literal `ArdoCodeBlock` samples use Ferromark's standalone fence renderer,
sharing Markdown's title/label, highlighted-line, and line-number metadata.
Generated JSX children retain native blank/trailing lines; copying uses the
original `code` prop or the outdented literal children. Explicit component
title, label, line numbers, and literal highlighted-line props take precedence
over metadata defaults. Dynamic props, interpolated templates, and custom JSX
children keep their runtime behavior.

`highlightCode` from `ardo/vite` continues to return HTML and `__html` remains
a supported `ArdoCodeBlock` input. That compatibility helper uses Ferriki Core
0.13 and the existing HTML metadata adapter. `MarkdownConfig.theme` retains its
Ferriki `ThemeInput` type. Ferromark bundles its own native highlighter: updating
the direct Core dependency does not update that bundled copy. The HTML helper
and native JSX renderer can produce different markup; both preserve their
respective public output contracts.
