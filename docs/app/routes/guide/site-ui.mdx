# Site UI Configuration

Build-time options belong in `ardo()` config. Site chrome belongs in React. Define the header, left
rail, sidebar panels, footer, edit links, and last-updated metadata in your app's `root.tsx`.

## Minimal Root

Every Ardo app needs the generated config. Navigation is composed with React components.

```tsx
import {
  ArdoGeneratedSidebar,
  ArdoHeader,
  ArdoNav,
  ArdoNavLink,
  ArdoRoot,
  ArdoSidebar,
  ArdoSidebarSection,
} from "ardo/ui"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader>
        <ArdoNav>
          <ArdoNavLink to="/guide/getting-started">Guide</ArdoNavLink>
        </ArdoNav>
      </ArdoHeader>

      <ArdoSidebar>
        <ArdoSidebarSection id="guide" label="Guide" to="/guide/getting-started">
          <ArdoGeneratedSidebar section="guide" />
        </ArdoSidebarSection>
      </ArdoSidebar>
    </ArdoRoot>
  )
}
```

`ArdoRoot` owns the Ardo providers, the current page's content, and the shell slots supplied as JSX
children. It is the part of the page that hydrates in the browser.

## Layout: The HTML Shell

Ardo renders every page inside an HTML shell: `<html>`, `<head>`, and `<body>`. The shell is
rendered on the server only, during `ardo dev` and `ardo build`; the root component inside it
hydrates. By default, Ardo uses `ArdoRootLayout` from `ardo/ui`. It adds the charset and viewport
tags, the theme bootstrap script, favicons, the page's title and meta tags, stylesheets, and the
client script. Most sites do not need a `Layout` export.

Export `Layout` from `root.tsx` to pass options to `ArdoRootLayout`:

```tsx
import type { ReactNode } from "ardo/react"
import { ArdoRootLayout } from "ardo/ui"
import logo from "./assets/logo.svg"

export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout favicon={logo}>{children}</ArdoRootLayout>
}
```

For a fully custom shell, render `ArdoHead` in `<head>` and `ArdoScripts` at the end of `<body>`.
Both come from `ardo/runtime`. `ArdoHead` renders the page's `meta` descriptors, stylesheets, and
module preloads; `ArdoScripts` loads the client entry that hydrates the page. The shell must render
`children`:

```tsx
import type { ReactNode } from "ardo/react"
import { ArdoHead, ArdoScripts } from "ardo/runtime"

export function Layout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <head>
        <meta charSet="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <ArdoHead />
      </head>
      <body>
        {children}
        <ArdoScripts />
      </body>
    </html>
  )
}
```

A custom shell does not include `ArdoRootLayout`'s theme bootstrap or favicons. Prefer wrapping
`ArdoRootLayout` unless the site needs full control over the document.

## RootLayout Theme Policy

By default, `ArdoRootLayout` uses `theme="auto"`: it applies a stored `ardo-theme` preference first
and falls back to `prefers-color-scheme`. Set an explicit theme policy when a site should not be
user-selectable:

```tsx
export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout theme="light">{children}</ArdoRootLayout>
}
```

| Theme policy | Behavior                                                                 |
| ------------ | ------------------------------------------------------------------------ |
| `auto`       | Stored user preference wins; system preference is the fallback. Default. |
| `light`      | Always render light mode and clear stale stored theme preferences.       |
| `dark`       | Always render dark mode and clear stale theme preferences.               |
| `system`     | Always follow `prefers-color-scheme` and clear stored preferences.       |

## ArdoRoot

`ArdoRoot` accepts site-wide content settings as props and shell components as children.

| Prop          | Type                                                                               | Purpose                                                                    |
| ------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `config`      | `ArdoConfig`                                                                       | Generated site config from `virtual:ardo/config`.                          |
| `editLink`    | `{ pattern: string; text?: string }`                                               | Site-wide edit-link pattern for Markdown pages.                            |
| `lastUpdated` | `{ enabled?: boolean; text?: string; formatOptions?: Intl.DateTimeFormatOptions }` | Site-wide last-updated display settings.                                   |
| `labels`      | `ArdoLabelsInput`                                                                  | Override default UI chrome strings.                                        |
| `scrollMode`  | `"viewport" \| "document"`                                                         | Use the viewport shell (default) or let the document scroll.               |
| `tocLabel`    | `string`                                                                           | Label for the table-of-contents panel.                                     |
| `className`   | `string`                                                                           | Replace the default layout class.                                          |
| `children`    | `ReactNode`                                                                        | `ArdoHeader`, `ArdoSidebar`, `ArdoFooter`, and optional content overrides. |

## Header

Use `ArdoHeader` for the default responsive header. Put `ArdoNav` links directly inside it. Use
`ArdoHeaderActions` for right-side actions.

```tsx
import { ArdoHeader, ArdoHeaderActions, ArdoNav, ArdoNavLink, ArdoSocialLink } from "ardo/ui"
import logo from "./assets/logo.svg"
;<ArdoHeader logo={logo} title="My Docs" searchPlaceholder="Search documentation...">
  <ArdoNav>
    <ArdoNavLink to="/guide/getting-started">Guide</ArdoNavLink>
    <ArdoNavLink to="/api-reference">API</ArdoNavLink>
  </ArdoNav>
  <ArdoHeaderActions>
    <ArdoSocialLink href="https://github.com/example/project" icon="github" />
  </ArdoHeaderActions>
</ArdoHeader>
```

If `brand.logo` is configured in `ardo()`, `ArdoRoot` passes it to the default header unless the
header sets its own `logo`.

| Header prop         | Purpose                                                      |
| ------------------- | ------------------------------------------------------------ |
| `logo`              | String URL or `{ light, dark }` logo variants.               |
| `title`             | Header title. Defaults to `config.title`.                    |
| `search`            | Set to `false` to hide search. Defaults to `true`.           |
| `searchPlaceholder` | Placeholder for the search input.                            |
| `themeToggle`       | Set to `false` to hide the theme toggle. Defaults to `true`. |
| `className`         | Replace the default header class.                            |

## Sidebar Sections

The left navigation is always a rail plus a panel. Define both with `ArdoSidebarSection`: the section
props create the rail item, and the section children create the panel.

```tsx
import { ArdoGeneratedSidebar, ArdoSidebar, ArdoSidebarSection } from "ardo/ui"
import { BookOpen, Code2 } from "lucide-react"
;<ArdoSidebar>
  <ArdoSidebarSection
    id="guide"
    label="Guide"
    to="/guide/getting-started"
    icon={<BookOpen size={18} />}
  >
    <ArdoGeneratedSidebar section="guide" />
  </ArdoSidebarSection>

  <ArdoSidebarSection id="api-reference" label="API" to="/api-reference" icon={<Code2 size={18} />}>
    <ArdoGeneratedSidebar section="api-reference" />
  </ArdoSidebarSection>
</ArdoSidebar>
```

`ArdoGeneratedSidebar` renders the Markdown and API navigation generated from route files for the
given top-level section. For fully manual navigation, compose links and groups directly:

```tsx
<ArdoSidebarSection id="guide" label="Guide" to="/guide/getting-started">
  <ArdoSidebarGroup title="Guide">
    <ArdoSidebarLink to="/guide/getting-started">Getting Started</ArdoSidebarLink>
    <ArdoSidebarLink to="/guide/configuration">Configuration</ArdoSidebarLink>
  </ArdoSidebarGroup>
</ArdoSidebarSection>
```

## Footer

Pass `ArdoFooter` as a child of `ArdoRoot`.

```tsx
<ArdoFooter
  sponsor={{ text: "Example Co", link: "https://example.com" }}
  message="Released under the MIT License."
  copyright="Copyright 2026 Example Co"
/>
```

## Edit Links and Last Updated

`editLink` and `lastUpdated` are site-wide content settings. Ardo applies them to Markdown and MDX
document pages, and page frontmatter can opt out with `editLink: false` or `lastUpdated: false`.

```tsx
<ArdoRoot
  config={config}
  editLink={{
    pattern: "https://github.com/example/project/edit/main/docs/app/routes/:path",
    text: "Edit this page on GitHub",
  }}
  lastUpdated={{
    enabled: true,
    text: "Last updated",
    formatOptions: { dateStyle: "medium" },
  }}
  tocLabel="On this page"
>
  {/* Header, sidebar, and footer here */}
</ArdoRoot>
```

The `:path` placeholder receives the route file path relative to the generated Markdown route root.

## Route-Level Chrome

For route-level chrome suppression, export a `handle` from the route:

```tsx title="app/routes/landing.tsx"
export const handle = { layout: "bare", chrome: false }
```

`chrome: false` removes header and footer for that route. `layout: "bare"` removes sidebar and rail
rendering.

### Bare routes with custom chrome

Use `export const handle = { layout: "bare", chrome: false }` on a route that owns
its site header and footer. Ardo reserves no space for an absent header, renders
no additional skip link, and leaves the main element's padding, background, and
overflow to your site. Provide your own skip link for keyboard navigation.

Bare routes that retain Ardo's header keep its offset and built-in skip link.
Documentation routes retain the existing inner-scroll layout.

## Document Scrolling with Site-Owned Chrome

Set `scrollMode="document"` when the site's header or footer lives outside Ardo's layout, or when
the page should use normal document scrolling. Ardo keeps the existing viewport shell by default.
In document mode, the document scrolls, the sidebar and page rail stick below the configured header
height, and an external footer remains reachable after the documentation content. The mode also
applies when `className` replaces Ardo's default layout class. Since that prop still replaces the
default class, provide any root display or width rules your custom layout needs.

Place a sticky custom header and footer beside `ArdoRoot`. When both are external, disable Ardo's
header and footer so the page has one of each:

```tsx
export default function Root() {
  return (
    <>
      <SiteHeader />
      <ArdoRoot config={config} scrollMode="document" header={false} footer={false}>
        <ArdoSidebar />
      </ArdoRoot>
      <SiteFooter />
    </>
  )
}
```

The existing `--ardo-layout-headerHeight` variable sets the sticky offsets and anchor spacing. Put
its value on `ArdoRootLayout` through a `Layout` export so Ardo and the site header share it, then update it at the breakpoint
where a mobile header grows:

```tsx
export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout className="docs-site">{children}</ArdoRootLayout>
}
```

```css
.docs-site {
  --ardo-layout-headerHeight: 4rem;
}

@media (max-width: 640px) {
  .docs-site {
    --ardo-layout-headerHeight: 6rem;
  }
}

.site-header {
  position: sticky;
  top: 0;
  height: var(--ardo-layout-headerHeight);
}
```

A sticky header stays in document flow, so it needs no extra top padding. A fixed header is outside
that flow; reserve its height once in the site wrapper with `padding-top: var(--ardo-layout-headerHeight)`.
For an MDX route that owns its chrome, export:

```mdx
export const handle = { chrome: false }
```

The route's external header and footer follow the same offset rule, while Ardo keeps the sidebar
and page rail. Provide a site-owned skip link for routes that suppress Ardo's chrome.
