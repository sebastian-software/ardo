# Getting Started

Use the Ardo skill with your coding assistant to set up a new site, adopt Ardo in an existing repository, or upgrade a site. The skill follows the [Agent Instructions](/guide/agent-instructions) and [tested Basic example](/guide/reference-projects). Ardo 6 retires the `create-ardo` starter; [manual installation](#manual-installation) remains available.

## Use the Ardo Skill or Ask Your Assistant

Install the [Ardo skill folder](https://github.com/sebastian-software/ardo/tree/main/skills/ardo) using your assistant's normal skill support. Its [SKILL.md](https://raw.githubusercontent.com/sebastian-software/ardo/main/skills/ardo/SKILL.md) is also available to read directly. Then open the target repository and ask:

```prompt
Set up Ardo in this repository. Use the Ardo skill, inspect the project, and adapt the tested Basic example. For a new site, use the latest published Ardo release unless I selected a version. Preserve existing application behavior and deployment choices. Run the applicable checks and production build, then verify the home page and a guide in the browser.
```

The skill selects the matching documentation and example before editing. For an existing Ardo site, it inspects the installed version and treats a major upgrade as a separate choice.

Without skill support, ask your assistant to read `https://ardo-docs.dev/llms.txt` and follow [Agent Instructions](/guide/agent-instructions). The index points to the setup, adoption, upgrade, and optional feature guides. Use the versioned index for a repeatable setup: this guide covers Ardo 6 at `/v6/llms.txt`, with the complete Markdown context at `/v6/llms-full.txt`. Match those instructions and `examples/basic` to the selected release's Git tag. For development before a release, use the instructions, example, and built package from the same checkout revision.

Use the Basic example for the common setup. Add optional API documentation, external content, or deployment configuration through the recipes in [Basic Example](/guide/reference-projects). For an existing app, see [Adopt Ardo in an Existing Project](/guide/adopt-ardo).

## Prerequisites

You'll need:

- [Node.js](https://nodejs.org/) version 22.22.0 or higher
- Linux or Windows on x64/arm64, or macOS on Apple Silicon, with optional native package dependencies enabled
- [pnpm](https://pnpm.io/) (recommended) or npm/yarn

## Manual Installation

For setup without an agent, follow these steps and the matching [Basic example](/guide/reference-projects). In an existing workspace, merge the required configuration into your application rather than creating a replacement shell. Ardo's CLI supplies the build integration; React handles UI configuration.

### 1. Create a new project

```bash
mkdir my-docs
cd my-docs
pnpm init
```

### 2. Install dependencies

```bash
pnpm add ardo@6
pnpm add -D typescript@6
```

### 3. Add package scripts

Ardo manages React, React DOM, and Vite as its own dependencies. Its CLI starts the development server, builds the static site, and previews the generated client output:

```json
{
  "scripts": {
    "dev": "ardo dev",
    "build": "ardo build",
    "preview": "ardo preview"
  }
}
```

When you use pnpm, add a build-script allowlist so esbuild can
prepare Vite's native dependency:

```yaml
# pnpm-workspace.yaml
packages:
  - "."

allowBuilds:
  esbuild: true
```

### 4. Add optional Ardo configuration

Ardo works without a configuration file. Add `ardo.config.ts` when you want to set site metadata, theme, deployment, or content options. UI configuration (navigation, sidebar, footer) stays in JSX props in `root.tsx`:

**`ardo.config.ts`**:

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "My Documentation",
  description: "My awesome documentation site",
})
```

The site serves from the domain root. For a subpath, such as a GitHub Pages project site, set `base`; the [Deployment](/guide/deployment) guide covers every host.

Add a `vite.config.ts` only when you need extra Vite plugins or Vite-specific settings. The Ardo CLI
adds its build integration automatically, so a custom Vite config does not need to call `ardo()`.

### 5. Create app files

An Ardo project needs one app file besides its content: `app/root.tsx`. Its default export is the root component. Ardo renders the HTML shell around it, so you only add a `Layout` export when you need to change that shell (see [Site UI](/guide/site-ui)). Ardo generates the route table from `app/routes/` and supplies the client and server entries itself.

**`app/root.tsx`**:

```tsx
import type { ArdoMetaFunction } from "ardo/runtime"
import {
  ArdoGeneratedSidebar,
  ArdoHeader,
  ArdoNav,
  ArdoNavLink,
  ArdoRoot,
  ArdoSidebar,
  ArdoSidebarSection,
} from "ardo/ui"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export const meta: ArdoMetaFunction = () => [{ title: "My Documentation" }]

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader>
        <ArdoNav>
          <ArdoNavLink to="/guide/getting-started">Guide</ArdoNavLink>
        </ArdoNav>
      </ArdoHeader>

      <ArdoSidebar>
        <ArdoSidebarSection id="guide" label="Guide" to="/guide/getting-started">
          <ArdoGeneratedSidebar section="guide" />
        </ArdoSidebarSection>
      </ArdoSidebar>
    </ArdoRoot>
  )
}
```

`root.tsx` can also export `ErrorBoundary`. Ardo renders it inside the root for a missing page and uses it in place of the root for a render error. Ardo uses `ArdoErrorBoundary` when you leave it out.

**`tsconfig.json`**:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "jsxImportSource": "ardo",
    "types": ["ardo/vite/client", "ardo/virtual"],
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["app/**/*", "*.ts"]
}
```

Import React hooks and types from `ardo/react`. Import Ardo's runtime APIs, such as
`ArdoLink`, `useArdoPath`, and `ArdoMetaFunction`, from `ardo/runtime`, and components from
`ardo/ui`. Do not import runtime values from the package root `ardo` in browser code: that
entry also contains Node-only build code.

These public entry points provide types without a separate React dependency. Ardo also
resolves bare React imports to its own runtime during development and builds, including
imports in installed component libraries. Components and the renderer therefore use the
same React installation even if an ancestor package has another version. Other application
dependencies must still be declared and installed in the documentation package.

For portals and other React DOM APIs, use `ardo/react-dom`. Tailwind and other Vite plugins
are optional; install them in the documentation package when you use them.

### 6. Create your first pages

Create a home page so the root URL and header logo have a destination:

**`app/routes/home.tsx`**:

```tsx
import { ArdoHero } from "ardo/ui"

export default function HomePage() {
  return (
    <ArdoHero
      name="My Documentation"
      tagline="Guides and examples for your project."
      actions={[{ text: "Get started", link: "/guide/getting-started", theme: "brand" }]}
    />
  )
}
```

Add the guide linked from your home page, header, and sidebar:

**`app/routes/guide/getting-started.mdx`**:

```markdown
---
title: Getting Started
---

# Getting Started

Welcome to your documentation site!
```

Run `pnpm dev` and open `http://localhost:5173`. You should see your home page; choose **Get started** to open the guide.

<Tip>
  The tested Basic example contains the complete root component and configuration. Use the
  version-matched reference and Agent Instructions when adapting this setup to your repository.
</Tip>

## Development

Start the development server:

```bash
pnpm dev
```

Your site will be running at `http://localhost:5173`. Changes to MDX and TSX routes flow through Vite's development server.

## Production Build

When you're ready to publish:

```bash
pnpm build
```

The output lands in `build/client/`: one prerendered `index.html` per page, a `404.html`, and the hashed assets, ready for any static host. The build should report two prerendered pages and no broken internal links. It checks every internal link and anchor in the generated HTML. Preview it locally before deploying:

```bash
pnpm preview
```

## Project Structure

Here's what an Ardo project looks like. Files under `app/routes/` become pages, `app/root.tsx` holds the site chrome, and everything else is configuration:

```text
my-docs/
├── app/
│   ├── routes/                  # Pages: .md, .mdx, and .tsx files
│   │   ├── guide/
│   │   │   └── getting-started.mdx
│   │   └── home.tsx             # Home page
│   └── root.tsx                 # Root component (header, sidebar, footer)
├── ardo.config.ts               # Optional site configuration
├── vite.config.ts               # Optional extra Vite plugins or settings
├── pnpm-workspace.yaml          # pnpm build-script allowlist, when using pnpm
├── tsconfig.json
└── package.json
```

Use the [Basic example](/guide/reference-projects) from the Git tag matching your installed Ardo version. Add API inputs, external Markdown, or hosting configuration through the optional recipes.
