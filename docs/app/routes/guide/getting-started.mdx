# Getting Started

Start with [Agent Instructions](/guide/agent-instructions) for a new site, an existing React repository, or an upgrade. The instructions use [a tested Basic example](/guide/reference-projects) matched to your Ardo version. Ardo 6 retires the `create-ardo` starter.

## Set Up with an Agent

Give your coding agent this instruction together with the repository:

```text
Set up Ardo 6 in this repository. Read https://ardo-docs.dev/v6/llms.txt,
then follow https://ardo-docs.dev/v6/guide/agent-instructions. Inspect the
project and adapt the tested Basic example from the matching Ardo
release tag. Preserve existing application behavior and deployment choices.
Run the applicable typecheck, tests, and production build, and report the results.
```

Use `/v6/llms-full.txt` when the agent needs the complete documentation as Markdown. The unversioned text files follow the current major; use the versioned URLs for a repeatable setup. For development before a release, use the instructions, Basic example, and built package from the same checkout revision.

Use the Basic example for the common setup. Add optional API documentation, external content, or deployment configuration through the recipes in [Basic Example](/guide/reference-projects). For an existing app, see [Adopt Ardo in an Existing Project](/guide/adopt-ardo).

## Prerequisites

You'll need:

- [Node.js](https://nodejs.org/) version 22.22.0 or higher
- Linux or Windows on x64/arm64, or macOS on Apple Silicon, with optional native package dependencies enabled
- [pnpm](https://pnpm.io/) (recommended) or npm/yarn

## Manual Installation

For setup without an agent, follow these steps and the matching [Basic example](/guide/reference-projects). In an existing workspace, merge the required configuration into your application rather than creating a replacement shell. Ardo's CLI supplies the build integration; React handles UI configuration.

### 1. Create a new project

```bash
mkdir my-docs
cd my-docs
pnpm init
```

### 2. Install dependencies

```bash
pnpm add ardo@6
pnpm add -D typescript@6
```

### 3. Add package scripts

Ardo manages React, React DOM, React Router, and Vite as its own dependencies. Its CLI starts the development server, builds the static site, and previews the generated client output:

```json
{
  "scripts": {
    "dev": "ardo dev",
    "build": "ardo build",
    "preview": "ardo preview"
  }
}
```

When you use pnpm, add a build-script allowlist so esbuild can
prepare Vite's native dependency:

```yaml
# pnpm-workspace.yaml
packages:
  - "."

allowBuilds:
  esbuild: true
```

### 4. Add optional Ardo configuration

Ardo works without a configuration file. Add `ardo.config.ts` when you want to set site metadata, theme, deployment, or content options. UI configuration (navigation, sidebar, footer) stays in JSX props in `root.tsx`:

```ts
import { defineArdoConfig } from "ardo/config"

export default defineArdoConfig({
  title: "My Documentation",
  description: "My awesome documentation site",
})
```

Add a `vite.config.ts` only when you need extra Vite plugins or Vite-specific settings. The Ardo CLI
adds its build integration automatically, so a custom Vite config does not need to call `ardo()`.

### 5. Create React Router configuration

Ardo uses React Router 8 under the hood. For a static documentation site, you want pre-rendering enabled and SSR off:

```ts
import type { ReactRouterConfig } from "ardo/config"

export default {
  ssr: false,
  prerender: true,
} satisfies ReactRouterConfig
```

### 6. Create app files

Create an Ardo root component. React Router supplies the default client entry. The server entry delegates to Ardo, which renders the complete page with its shared runtime. Customized entry files remain supported.

**`app/root.tsx`**:

```tsx
import {
  ArdoGeneratedSidebar,
  ArdoHeader,
  ArdoNav,
  ArdoNavLink,
  ArdoRoot,
  ArdoRootLayout,
  ArdoSidebar,
  ArdoSidebarSection,
} from "ardo/ui"
import type { ReactNode } from "ardo/react"
import config from "virtual:ardo/config"
import "ardo/ui/styles.css"

export function Layout({ children }: { children: ReactNode }) {
  return <ArdoRootLayout>{children}</ArdoRootLayout>
}

export default function Root() {
  return (
    <ArdoRoot config={config}>
      <ArdoHeader>
        <ArdoNav>
          <ArdoNavLink to="/guide/getting-started">Guide</ArdoNavLink>
        </ArdoNav>
      </ArdoHeader>

      <ArdoSidebar>
        <ArdoSidebarSection id="guide" label="Guide" to="/guide/getting-started">
          <ArdoGeneratedSidebar section="guide" />
        </ArdoSidebarSection>
      </ArdoSidebar>
    </ArdoRoot>
  )
}
```

**`app/entry.server.tsx`**:

```tsx
export { default, streamTimeout } from "ardo/entry.server"
```

**`tsconfig.json`**:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "jsxImportSource": "ardo",
    "types": ["ardo/vite/client", "ardo/virtual"],
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["app/**/*", "*.ts"]
}
```

Import hooks and React types from `ardo/react` and routing APIs from `ardo/router`.
These public entry points provide types without separate React or router dependencies.
Ardo also resolves bare React and router imports to its own runtime during development
and builds, including imports in installed component libraries. Components and the
renderer therefore use the same React installation even if an ancestor package has
another version. Other application dependencies must still be declared and installed
in the documentation package.

For portals and other React DOM APIs, use `ardo/react-dom`. For custom client or server
entries, use `ardo/react-dom/client`, `ardo/react-dom/server`, and `ardo/router/dom`. Tailwind and other Vite plugins
are optional; install them in the documentation package when you use them.

### 7. Create your first document

Create `app/routes/guide/getting-started.mdx`:

```markdown
---
title: Getting Started
---

# Getting Started

Welcome to your documentation site!
```

That's it. Run `pnpm dev` and you've got a documentation site.

## Development

Start the development server:

```bash
pnpm dev
```

Your site will be running at `http://localhost:5173`. Changes to MDX and TSX routes flow through Vite's development server.

## Production Build

When you're ready to publish:

```bash
pnpm build
```

The output lands in `build/client/` — a fully static site ready for any hosting platform. Preview it locally before deploying:

```bash
pnpm preview
```

## Project Structure

Here's what an Ardo project looks like. If you've worked with React Router, the layout will feel natural:

```
my-docs/
├── app/
│   ├── routes/                  # Your MDX/MD content files
│   │   ├── guide/
│   │   │   └── getting-started.mdx
│   │   └── home.tsx             # Home page
│   ├── entry.server.tsx         # Delegates to Ardo
│   └── root.tsx                 # Root layout
├── ardo.config.ts               # Optional site configuration
├── vite.config.ts               # Optional extra Vite plugins or settings
├── react-router.config.ts       # React Router configuration
├── pnpm-workspace.yaml          # pnpm build-script allowlist, when using pnpm
├── tsconfig.json
└── package.json
```

Use the [Basic example](/guide/reference-projects) from the Git tag matching your installed Ardo version. Add API inputs, external Markdown, or hosting configuration through the optional recipes.
